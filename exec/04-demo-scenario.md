# 시연 시나리오

이 문서는 처음 보는 사람이 iRead의 핵심 기능을 같은 순서로 재현할 수 있도록 화면별 클릭 위치, 입력값과 예상 결과를 설명한다. 기본 시연 시간은 약 15~20분이다.

## 1. 시연 목표

1. 교수자가 아동별 학습 현황과 커리큘럼을 관리한다.
2. 아동이 실력 도전, 맞춤 훈련과 개인화 이야기를 수행한다.
3. 음성·시선 결과가 저장되고 교수자 화면에 반영된다.
4. 교수자가 검사·학습·이야기 이력과 보고서를 확인한다.

## 2. 사전 준비

### 2.1 시연 데이터 초기화

전체 서비스가 실행 중인 상태에서 한 번 실행한다.

```powershell
.\reset-qa-demo.bat
```

```bash
./reset-qa-demo.sh
```

### 2.2 서비스 상태 확인

```bash
docker compose ps
```

| 대상 | 주소 | 정상 조건 |
| --- | --- | --- |
| 교수자 앱 | `http://localhost:5173` | landing 화면 표시 |
| 아동 앱 | `http://localhost:5174` | 아동 학습 로그인 화면 표시 |
| Backend | `http://localhost:8080/actuator/health` | `status: UP` |
| AI 서비스 | `http://localhost:8081/health` | HTTP 200 |
| Mailpit | `http://localhost:8025` | 웹 메일함 표시 |
| 시선 브리지 | `http://localhost:8765/api/status` | 실제 장치 또는 simulation 상태 |

### 2.3 계정과 시연 아동

```text
교수자 이메일: test@test.com
교수자 비밀번호: qwer1234
기본 시연 아동: 김도윤 (studentId 2001)
추가 비교 아동: 이서연 (2002), 박지호 (2103)
```

모든 계정과 인적 정보는 시연용 가상 데이터다.

## 3. 전체 시연 순서

```text
교수자 로그인
→ 아동 목록과 김도윤의 기존 분석 확인
→ 아동 앱에서 김도윤 선택
→ 필요 시 실력 도전
→ 오늘의 맞춤 훈련 수행
→ 개인화 이야기와 분기 선택
→ 교수자 화면에서 새 결과 확인
→ 보고서 생성
```

## 4. 교수자 화면: 기준 데이터 확인

### 4.1 Landing에서 로그인으로 이동

| 순서 | 화면·클릭 위치 | 실행 | 예상 결과 |
| ---: | --- | --- | --- |
| 1 | 브라우저 주소창 | `http://localhost:5173` 접속 | iRead 소개 landing 표시 |
| 2 | 화면 우측 상단 또는 본문 좌측의 `교수자 웹 바로가기` | 버튼 클릭 | `/login`으로 이동 |
| 3 | 로그인 카드의 `이메일 주소` | `test@test.com` 입력 | 이메일 입력 표시 |
| 4 | 바로 아래 `비밀번호` | `qwer1234` 입력 | 비밀번호가 가려져 표시 |
| 5 | 로그인 카드 하단의 `로그인` | 버튼 클릭 | `/teacher/students` 아동 목록으로 이동 |

로그인 실패 시 Backend가 실행 중인지, 이메일 앞뒤 공백이 없는지, DB dump 또는 QA 초기화가 적용됐는지 확인한다.

### 4.2 아동 목록

| 순서 | 화면·클릭 위치 | 실행 | 예상 결과 |
| ---: | --- | --- | --- |
| 1 | 좌측 sidebar 첫 메뉴 `아동 목록` | 선택 상태 확인 | 김도윤·이서연·박지호 카드 표시 |
| 2 | 본문 아동 카드 중 `김도윤` | 카드 클릭 | 김도윤의 `학습 현황` 화면으로 이동 |
| 3 | 좌측 sidebar 상단 아동 전환 영역 | 현재 아동 이름 확인 | 김도윤이 선택된 상태 |

아동 카드를 선택한 이후 좌측 sidebar에는 `학습 현황`, `커리큘럼 관리`, `학습 이력`, `검사 이력`, `이야기 이력`, `보고서`, `아동 정보 관리`가 표시된다.

### 4.3 학습 현황

| 순서 | 화면·클릭 위치 | 실행 | 예상 결과 |
| ---: | --- | --- | --- |
| 1 | 좌측 `학습 현황` | 클릭 | 최근 학습 기록과 추이 chart 표시 |
| 2 | 본문 상단 아동 요약 | 이름과 상태 확인 | 김도윤 정보가 표시 |
| 3 | 학습 변화 chart 상단 tab | 정확도·읽기 속도 등 tab 전환 | 선택 지표의 날짜별 추이 갱신 |
| 4 | 최근 학습 기록 영역 | 가장 최근 항목 확인 | 시연 전 기준 이력이 표시 |

### 4.4 커리큘럼 관리

| 순서 | 화면·클릭 위치 | 실행 | 예상 결과 |
| ---: | --- | --- | --- |
| 1 | 좌측 `커리큘럼 관리` | 클릭 | 훈련 영역과 다음 회차 목록 표시 |
| 2 | 본문 상단 훈련 영역 tab | 영역을 차례로 클릭 | 영역별 전체 훈련 목록 전환 |
| 3 | `다음 회차 목록` | 순서와 상태 확인 | 김도윤 다음 커리큘럼의 훈련 5개 표시 |
| 4 | 준비된 훈련 항목 | 미리보기 또는 상세 버튼 클릭 | 아동에게 제공될 문항과 목표 표시 |

시연 중 커리큘럼을 수정한다면 저장 완료 안내가 나온 뒤 아동 앱으로 이동한다. 준비 완료 전 상태의 훈련은 아동 앱에 노출되지 않을 수 있다.

### 4.5 기존 이력 확인

| 좌측 메뉴 | 본문에서 클릭할 위치 | 확인 내용 |
| --- | --- | --- |
| `학습 이력` | 완료한 커리큘럼 → 학습 목록 → 훈련 항목 | 문항별 응답, 정확도, 발음·시선 상세 |
| `검사 이력` | 완료한 검사 → 검사 지표 tab → 문항 영역 | 검사 간 비교와 문항별 결과 |
| `이야기 이력` | 이야기 선택 card | 장면, 진행 일차, 아동 선택과 교사 수정 이력 |
| `보고서` | 기간 시작일·종료일 | 선택 기간의 종합 분석과 저장된 보고서 |

이 시점의 값을 간단히 기억하거나 메모한 뒤 아동 시연 후 다시 비교한다.

## 5. 아동 앱 로그인

새 브라우저 창 또는 다른 browser profile에서 `http://localhost:5174`를 연다.

| 순서 | 화면·클릭 위치 | 실행 | 예상 결과 |
| ---: | --- | --- | --- |
| 1 | 중앙 로그인 카드의 `이메일 주소` | `test@test.com` 입력 | 1단계 교사 로그인 입력 완료 |
| 2 | 바로 아래 `비밀번호` | `qwer1234` 입력 | 비밀번호가 가려져 표시 |
| 3 | 카드 하단 `다음` | 클릭 | 2단계 `아동 프로필을 선택해 주세요` 표시 |
| 4 | 중앙 profile 목록의 `김도윤` | profile card 클릭 | 김도윤 카드가 선택 상태로 변경 |
| 5 | 카드 하단 우측 `학습 시작` | 클릭 | 학습 진입 상태에 따라 실력 도전 또는 메인 섬으로 이동 |

`실력 도전`으로 자동 이동하면 신규 또는 미완료 검사가 필요한 상태다. 이 경우 6장을 먼저 수행한다. 메인 섬이 보이면 7장으로 이동한다.

## 6. 아동 화면: 실력 도전

### 6.1 시작

| 순서 | 화면·클릭 위치 | 실행 | 예상 결과 |
| ---: | --- | --- | --- |
| 1 | 실력 검증 panel 중앙 | 세 영역 card 확인 | 음운·짧은 글·유창성 영역 표시 |
| 2 | panel 하단 중앙 `시작하기` 또는 `이어하기` | 클릭 | 다음 검사 문항으로 이동 |
| 3 | 문항 시작 안내 | 시작 버튼이 있으면 클릭 | 첫 문항의 활동 화면 표시 |

### 6.2 문항 수행

문항 유형에 따라 화면 중앙의 글자·단어·문장 카드 또는 microphone 버튼을 사용한다.

1. 선택형은 정답이라고 생각하는 card를 클릭한다.
2. 음성형은 상단 microphone 상태가 사용 가능인지 확인하고 화면의 녹음 버튼을 누른다.
3. 문장 또는 단어를 읽은 뒤 녹음을 종료한다.
4. 결과 화면의 `다음 검증 이어가기`를 클릭한다.
5. 총 9문항을 완료하면 `실력 검증 완료` 화면이 나타난다.

검사에서는 틀린 응답도 결과로 저장되고 같은 문항을 무제한 재시도하지 않는다. 실제 Azure를 사용하지 않는 시연에서는 mock 음성 설정에 따라 결정적 결과가 반환된다.

### 6.3 완료

완료 화면의 하단 버튼을 클릭해 메인 섬으로 이동한다. 메인 섬에는 네 영역이 다음 위치에 표시된다.

| 위치 | 메뉴 |
| --- | --- |
| 좌측 상단 | `나의 성장` |
| 중앙 상단 | `이야기 나라` |
| 우측 상단 | `글자 연습` |
| 중앙 하단 | `실력 도전` |

## 7. 아동 화면: 오늘의 맞춤 훈련

| 순서 | 화면·클릭 위치 | 실행 | 예상 결과 |
| ---: | --- | --- | --- |
| 1 | 메인 섬 우측 상단 `글자 연습` | 섬 또는 label 클릭 | 오늘 커리큘럼의 훈련 경로 표시 |
| 2 | 경로에서 가장 앞의 활성 훈련 | 활성 card 클릭 | 훈련 소개 또는 첫 문항 표시 |
| 3 | 소개 화면 하단 시작 버튼 | 클릭 | 문항 활동 시작 |
| 4 | 화면 중앙의 선택·조합·읽기 활동 | 지시에 따라 응답 | 정답 또는 재시도 feedback 표시 |
| 5 | feedback 하단의 다음 버튼 | 클릭 | 다음 문항 또는 훈련 완료로 이동 |
| 6 | 완료 화면 하단 `다음 훈련 시작` | 클릭 | 다음 활성 훈련으로 이동 |

시선 활동이 포함된 경우:

1. 화면 우측 상단 eye tracker icon을 클릭한다.
2. `연결 확인` 또는 calibration 관련 버튼을 선택한다.
3. 실제 장치가 없으면 simulation 또는 마우스 fallback 상태를 확인한다.
4. 문장·단어 영역을 마우스로 따라가 시선 fixture 흐름을 시연한다.

음성 활동이 포함된 경우:

1. 우측 상단 microphone icon을 클릭해 장치 상태를 확인한다.
2. 화면 중앙의 녹음 버튼을 누르고 제시어를 읽는다.
3. 녹음을 끝낸 뒤 발음 결과와 재시도 안내를 확인한다.

모든 훈련을 끝내지 않아도 하나의 훈련 완료만으로 교수자 실시간 반영을 확인할 수 있다.

## 8. 아동 화면: 개인화 이야기

### 8.1 이야기 시작

| 순서 | 화면·클릭 위치 | 실행 | 예상 결과 |
| ---: | --- | --- | --- |
| 1 | 상단 iRead logo | 클릭해 메인 섬으로 이동 | 네 영역 표시 |
| 2 | 중앙 상단 `이야기 나라` | 클릭 | 이야기 책장 표시 |
| 3 | 본문 `새 이야기 시작하기` | 클릭 | 이야기 template 목록 표시 |

QA 데모는 합의된 이야기와 선택에서는 저장된 fixture를 사용하므로 외부 생성 공급자가 없어도 일정한 순서로 재생할 수 있다.

### 8.2 읽기와 분기

| 순서 | 화면·클릭 위치 | 실행 | 예상 결과 |
| ---: | --- | --- | --- |
| 1 | 이야기 본문과 그림 | 문장을 읽고 시선을 이동 | 현재 페이지 읽기 상태 기록 |
| 2 | 화면 하단 우측 `다음 페이지` | 클릭 | 다음 장면 표시 |
| 3 | 분기 페이지의 선택지 card | 하나 선택 | 선택한 card가 강조됨 |
| 4 | `이야기 이어 만들기` | 클릭 | 다음 이야기 생성 중 화면 표시 |
| 5 | 자유 입력을 시연할 경우 `직접 이야기하기` 아래 microphone | 녹음 시작·종료 | 인식 문장 확인 또는 재녹음 안내 |
| 6 | 생성 완료 후 다음 페이지 | 계속 읽기 | 선택 내용이 이후 사건에 반영 |

당일 마지막 페이지를 완료하면 `오늘 이야기 10페이지를 다 읽었어요` 화면이 나타난다. `이야기 나라로`를 눌러 책장으로 돌아간다.

## 9. 아동 화면: 성장과 장치 상태

### 9.1 나의 성장

1. 상단 iRead logo로 메인 섬에 돌아간다.
2. 좌측 상단 `나의 성장`을 클릭한다.
3. 학습·이야기 목표, 성장 단계와 이야기 친구를 확인한다.
4. 방금 완료한 활동이 성장 정보에 반영됐는지 확인한다.

### 9.2 Eye tracker와 microphone

| 위치 | 실행 | 정상 결과 |
| --- | --- | --- |
| 우측 상단 eye tracker icon | 클릭 | 연결 상태, calibration, 시선 pointer 설정 표시 |
| eye tracker menu의 `시선 포인터` | 켜기 | gaze 또는 마우스 fallback pointer 표시 |
| eye tracker menu의 `시선으로 버튼 누르기` | 시연 환경에 따라 켜기 | dwell 또는 gaze 기반 버튼 상호작용 가능 |
| 우측 상단 microphone icon | 클릭 | microphone 연결·권한 상태 표시 |

브라우저가 microphone 권한을 요청하면 시연 장치에서만 허용한다. 장치 연결 실패가 나면 브라우저 주소창의 사이트 권한과 Windows privacy 설정을 확인한다.

## 10. 교수자 화면: 아동 결과 확인

교수자 앱 창으로 돌아간다. sidebar 상단에서 김도윤이 선택됐는지 확인한다.

| 순서 | 좌측 메뉴·클릭 위치 | 실행 | 예상 결과 |
| ---: | --- | --- | --- |
| 1 | `학습 현황` | 최근 학습 기록 확인 | 방금 수행한 훈련 또는 검사가 최신 항목에 반영 |
| 2 | 학습 변화 chart tab | 해당 지표 선택 | 신규 결과가 날짜별 추이에 반영 |
| 3 | `학습 이력` | 최신 완료 커리큘럼 → 훈련 선택 | 문항 결과, 정확도, 발음·시선 상세 표시 |
| 4 | `검사 이력` | 최신 검사 선택 | 검사 지표와 문항별 답변 표시 |
| 5 | `이야기 이력` | 방금 읽은 이야기 선택 | 진행 페이지와 분기 선택 표시 |
| 6 | `보고서` | 기간에 오늘 포함 → 생성·저장 | 최신 데이터를 포함한 보고서 표시 |

화면이 자동 갱신되지 않았다면 연결 경고를 확인한 뒤 한 번 새로고침한다. 새로고침 후에도 결과가 없으면 Backend log와 browser Network tab의 API status를 확인한다.

## 11. 비밀번호 재설정 보조 시연

1. 교수자 화면에서 로그아웃한다.
2. 비밀번호 재설정을 요청한다.
3. `http://localhost:8025`의 Mailpit을 연다.
4. 가장 최근 iRead 메일을 선택한다.
5. 재설정 링크가 교수자 Frontend의 `/reset-password`로 연결되는지 확인한다.

실제 비밀번호를 바꾸면 이후 기본 시연 계정 정보와 달라지므로, 공통 시연에서는 링크 표시까지만 확인한다.

## 13. 빠른 문제 해결

| 증상 | 확인 순서 |
| --- | --- |
| 교수자·아동 로그인 실패 | Backend health → MySQL health → QA 계정 존재 → cookie·CORS |
| Frontend 빈 화면 | 해당 Frontend log → browser Console → `/api` proxy |
| 이야기·훈련 생성 실패 | Backend의 mock switch → AI health → 내부 API key 일치 → 공급자 key·quota |
| 발음 평가·STT·TTS 실패 | microphone 권한 → Azure key·region → `AI_MOCK_*` 설정 → AI log |
| 시선 pointer 없음 | 브리지 8765 → native executable → 장치 calibration → simulation fallback |
| 교수자에 결과 미반영 | 아동 제출 API 성공 → Backend DB 저장 → SSE 연결 → 새로고침 |
| DB migration 오류 | `flyway_schema_history` → 현재 dump 기준 → 빈 volume 재복원 여부 |

## 14. 화면 캡처 시 개인정보 점검

제출용 화면을 캡처한다면 다음 기준을 지킨다.

- `test@test.com`, 김도윤·이서연·박지호 등 가상 데이터만 사용한다.
- browser password manager, API key, `.env`, terminal secret을 포함하지 않는다.
- 실제 microphone·시선 원본과 로컬 사용자 경로가 보이지 않게 한다.
- 클릭 위치를 표시할 때는 화면 위 번호와 이 문서의 순서 번호를 동일하게 사용한다.
