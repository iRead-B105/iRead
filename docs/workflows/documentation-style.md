# 문서 작성 원칙

- 상태: accepted
- 최종 검토일: 2026-07-15

## 기본 어투

- README, 안내문, 보고서와 팀 입력 양식은 독자에게 설명하는 자연스러운 `~합니다`체로 작성한다.
- 정책, 명세, ADR, 계획과 내부 기준 문서는 간결한 `~한다`체로 작성한다.
- 한 문서 안에서는 문장 종결 방식을 일관되게 유지한다.
- 제목과 표 항목은 가능하면 짧은 명사형으로 작성한다.

## 표현 원칙

- 결론과 핵심 내용을 먼저 제시한다.
- 이미 확정된 사실을 불필요하게 강조하거나 같은 내용을 반복하지 않는다.
- 미결 사항은 필요한 기준 문서에서만 관리하고 소개 문서에 사족으로 나열하지 않는다.
- 번역투와 불필요한 영문 표현을 줄이되 코드, 명령어, 표준 기술명과 상태값은 원문을 유지한다.
- `source of truth`, `Clarification gate`처럼 자연스러운 한국어로 바꿀 수 있는 표현은 각각 `기준 문서`, `작업 전 확인`처럼 작성한다.
- 사실, 결정, 제안과 가정을 구분하며 가정은 `[ASSUMPTION]`, 미결 항목은 `[TBD]`, 외부 결정 대기는 `[BLOCKED]`로 표시한다.
- 독자가 행동해야 하는 내용은 조건과 완료 기준이 드러나도록 구체적으로 작성한다.

## 보고 방식

- 결과를 먼저 설명하고 필요한 근거와 남은 사항을 이어서 작성한다.
- 수행하지 않은 검증이나 해결되지 않은 위험은 숨기지 않고 간단히 밝힌다.
- 도구 실행 과정이나 내부 추론처럼 독자에게 필요하지 않은 내용은 문서에 남기지 않는다.
