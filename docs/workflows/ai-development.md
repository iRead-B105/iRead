# AI-assisted development workflow

- Status: accepted
- Last reviewed: 2026-07-15

어떤 AI 모델이나 개발 도구를 사용하더라도 루트 `AGENTS.md`의 범용 지침과 아래 순서를 따른다. 도구별 지침 파일은 만들지 않는다.

## 1. Orient

- `AGENTS.md`와 `docs/README.md`를 읽는다.
- 요청에 직접 관련된 source of truth와 ADR만 추가로 읽는다.
- 현재 파일 상태를 읽기 전용으로 확인한다.

## 2. Clarify

- 목표, 컨텍스트, 제약, 완료 조건을 식별한다.
- 결과를 바꿀 수 있는 미결 정보가 있으면 변경 전에 질문한다.
- 사용자 답변은 관련 컨텍스트 문서에 반영한다.

## 3. Plan

- 작고 독립적인 작업은 짧은 체크리스트로 수행한다.
- 여러 문서·저장소·세션을 포함하면 `PLANS.md`에 따라 실행 계획을 만든다.
- 계획에는 검증과 롤백/복구 관점을 포함한다.

## 4. Change

- source of truth를 먼저 수정한다.
- 관련 ADR, 인덱스, 요구사항과 계획을 같은 변경에서 동기화한다.
- 사용자 승인 없는 가정으로 서비스 책임이나 기술을 확정하지 않는다.

## 5. Verify

- `python tools/validate_harness.py`를 실행한다.
- Pull Request에서는 GitHub Actions의 `harness-validation` 결과를 확인한다.
- 위 하네스 검증은 문서 구조와 내부 링크만 확인한다.
- 소스 코드나 기능 변경 후의 테스트, 빌드, 린트, 타입 검사와 정적 분석은 사용자가 현재 요청에서 명시적으로 요청한 경우에만 실행한다.
- 검증 명령이 문서나 계획에 존재하더라도 자동 실행하지 않는다.
- 사용자가 요청하지 않은 검증은 실행하지 않고 최종 보고에 미실행 사실을 명시한다.
- 요구사항 수용 기준과 문서 간 일관성은 읽기 전용으로 검토할 수 있다.

## 6. Report and learn

- 결과를 먼저 설명하고 변경 파일, 실행한 검증과 요청이 없어 실행하지 않은 검증을 요약한다.
- 남은 미결 사항과 다음 사용자 결정을 명시한다.
- 반복된 오류나 피드백은 가장 가까운 `AGENTS.md` 또는 워크플로에 반영한다.
