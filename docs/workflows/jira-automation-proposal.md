# Jira 작업 관리 자동화 제안

- 상태: deferred
- 최종 검토일: 2026-07-25
- 적용 여부: 미적용

## 목적

팀과 Codex가 같은 작업 상태를 사용하고, 구현 진행 상황을 Jira에서 생성한 TODO 문서로 확인할 수 있는 운영 방안을 보관한다. 이 문서는 향후 검토용 제안이며 현재 에이전트에게 Jira 생성·수정 권한을 부여하지 않는다.

## 제안하는 기준 원본

- Git: 기능 명세, OpenAPI, SQL, ADR과 코드
- Jira: 작업 담당자, 우선순위와 진행 상태
- TODO 문서: Jira에서 단방향 생성하는 읽기 전용 현황

Git 문서와 Jira 상태를 양방향으로 자동 수정하지 않는다. 기존 [Backend·Frontend 구현 백로그](../planning/implementation-backlog.md)는 epic, 의존성과 작업 범위를 관리하는 기준 문서로 유지한다.

## 제안하는 상태 전환

자동화를 도입할 경우 다음 전환만 허용하는 방안을 검토한다.

1. 승인된 백로그 항목으로 Jira 작업을 생성한다.
2. 에이전트가 작업을 선점하면 `In Progress`로 전환한다.
3. PR을 생성하면 `In Review`로 전환하고 브랜치·PR을 연결한다.
4. PR이 병합되고 필수 CI가 통과하면 `Done`으로 전환한다.

우선순위, 요구사항, 수용 기준, 담당자와 작업 삭제는 자동 변경하지 않는다. CI 실패나 미충족 수용 기준이 있으면 완료 처리하지 않는다.

## 중복과 추적

- `BE-001`, `FE-001` 같은 구현 백로그 ID를 Jira의 외부 연결 키로 사용한다.
- 작업 생성 전에 같은 연결 키가 있는지 확인한다.
- 브랜치, 커밋과 PR에 Jira 키를 연결한다.
- 자동 변경 결과와 실패 원인을 Jira 활동 이력에 남긴다.

## TODO 문서 제안

도입 시 `docs/planning/todo.generated.md`를 Jira에서 생성하는 방안을 검토한다. 생성 문서는 Jira 키, 작업명, BE·FE 구분, 담당자, 우선순위, 상태, 브랜치, PR과 마지막 동기화 시각만 포함하며 직접 수정하지 않는다.

## 에이전트 권한 경계

자동화를 활성화하기 전 `AGENTS.md`에 허용 작업을 명시한다.

- 승인된 작업 생성
- 정해진 상태 전환
- 브랜치·PR·검증 결과 연결
- 진행 댓글 작성

작업 삭제, 우선순위·요구사항·수용 기준 변경과 미승인 외부 데이터 수정은 계속 사용자 확인 대상으로 유지한다.

## 도입 시 필요한 구성

- Jira 프로젝트 키와 상태 매핑
- GitHub와 Jira 인증정보를 위한 환경변수 또는 GitHub Secrets
- Jira 상태를 읽어 TODO 문서를 생성하는 동기화 도구
- 중복 방지 키와 실패 시 재시도·감사 기록
- 팀원의 작업 선점, 인계와 충돌 처리 규칙

인증정보는 저장소에 커밋하지 않는다.

## 재검토 조건

다음 정보가 준비되면 도입 여부를 다시 결정한다.

- Jira 프로젝트와 workflow 상태 확정
- 팀의 담당자·우선순위 운영 방식 합의
- Codex에 허용할 외부 변경 범위 승인
- TODO 문서의 갱신 주기와 커밋 방식 결정
