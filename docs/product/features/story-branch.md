# 기능 명세: AI 이야기 분기

- 상태: accepted
- 관련 기능: `ST-BRANCH-01`~`ST-BRANCH-05`

## 기대 결과

AI가 분기 질문과 서로 다른 선택지 3개를 생성한다. 아동이 음성으로 답하거나 버튼을 선택하면 시스템이 확정 텍스트와 현재 이야기 진행률을 AI에 전달하고, 진행률에 적합한 다음 장면을 생성해 보여준다.

이야기는 100페이지 동안 기승전결이 누적되고 100번째 페이지에서 결말을 맺는다. 생성된 이야기와 분기 기록은 담당 교사가 조회할 수 있으며, 아직 읽지 않은 생성 결과의 소제목·본문·선택지·이미지만 수정할 수 있다.

## 수용 기준

- 한 이야기는 10일 동안 매일 10페이지씩, 총 100페이지로 진행한다.
- 하루 읽기는 `4페이지 → 첫 번째 음성 분기 → 5페이지 → 두 번째 음성 분기 → 마무리 1페이지` 순서다.
- 각 페이지는 정확히 3문장이고 각 문장은 공백·숫자·문장부호를 제외한 한글 10~22음절이다. 자연스러운 호흡을 위해 13~19음절을 권장한다.
- 서술은 일관된 해요체 높임 단계를 유지하되 `~해요`, `~했어요`만 반복하지 않고 장면에 맞는 종결어미와 문장 시작을 자연스럽게 바꾼다.
- 직접 대사는 페이지당 0~1문장으로 제한하고 고정된 문장 위치를 요구하지 않는다. 장면에 필요할 때 사용하며 연속된 두 페이지에는 가능하면 한 번 이상 등장하게 한다.
- 문장 길이를 맞추기 위한 중간 절단이나 범용 마무리 문구 덧붙이기는 금지한다. 위반 문장은 재생성하거나 사건 의미를 보존해 교정한다.
- 첫 번째 분기 응답은 당일 5~9페이지에, 두 번째 분기 응답은 당일 10페이지와 이후 이야기 맥락에 반영한다.
- Backend가 이야기 생성 대사 수를 기준으로 일차와 페이지를 계산하며, 시작일로부터 열린 일차까지만 제공한다.
- 다음 일차의 첫 4페이지는 해당 일차가 열린 뒤 생성한다.
- 진행률은 총 100페이지 대비 생성·확정된 페이지 수를 사용하고, 10일차 100페이지에서만 `COMPLETED`가 된다.
- 이야기 생성은 현재 진행률에 해당하는 기승전결 단계, 이야기 목표, 핵심 갈등, 등장인물과 누적 인과관계를 유지한다.
- 100페이지 이전에는 핵심 갈등을 임의로 종결하지 않고, 100번째 페이지에는 앞선 선택과 사건을 회수한 명확한 결말을 생성한다.
- AI는 `branchIntent`를 후속 장면의 사건과 결과에 명시적으로 반영해야 하며 반대 결과를 임의로 생성하지 않는다.
- `branchIntent` 원문을 첫 문장에 기계적으로 복사하지 않고 기존 인물의 대사·행동·물건·소리와 그 결과로 자연스럽게 통합한다.
- AI 응답의 `content`는 아동에게 보여 줄 분기 질문이며 `branchPrompt.options`는 버튼으로 표시할 서로 다른 선택지 3개다.
- AI 응답의 `branchPrompt.subtitle`은 현재 분기 사건을 나타내는 짧은 소제목이며, 이어서 읽기 카드에는 가장 최근 분기의 소제목을 표시한다.
- `requiresBranchInput=true`인 대사에만 `branchPrompt`가 존재하고 일반 대사에서는 `null`이다.
- 아동은 음성으로 답하거나 AI가 생성한 버튼 선택지 중 하나를 선택할 수 있다.
- 버튼은 AI가 생성한 선택지 3개 중 하나만 고르지만, 음성은 세 선택지에 없는 아동의 자유 입력도 허용한다.
- 자유 음성 입력은 STT 결과를 아동이 확인하고 아동 안전성·길이 검증을 통과한 경우에만 최종 `branchIntent`로 사용한다.
- 선택지 3개는 난독증 아동이 한 번에 이해할 수 있는 짧고 구체적인 단일 행동이며, 서로 의미가 겹치거나 정답·오답을 암시하거나 위험한 행동을 권하지 않는다.
- 버튼 제출은 저장된 `optionNo`만 받고 Backend가 해당 선택지 문구를 확정 텍스트로 복원한다.
- 분기점에서 아동의 음성을 STT로 복원하거나 버튼 선택을 확정 텍스트로 변환해 `story_choices.content`에 저장한다.
- 한 분기 대사에는 최종 선택 한 건만 저장하고 STT 중간 실패와 재시도 결과는 저장하지 않는다.
- Backend가 `stories.progress`를 조회해 AI 요청의 `currentProgress`로 전달한다.
- 클라이언트는 진행률을 요청값으로 입력하지 않는다.
- AI의 `nextProgress`는 현재값 이상 `100` 이하이어야 한다.
- AI 생성 성공 후 선택 텍스트, 다음 장면·대사와 진행률 갱신을 하나의 DB 트랜잭션으로 처리한다.
- `nextProgress`가 `100`이면 이야기 상태를 `COMPLETED`로 변경한다.
- 같은 `story_line_id`의 재시도는 AI를 다시 호출하거나 저장 결과를 덮어쓰지 않고 최초 확정 결과를 `200 OK`로 반환한다.
- 최초 처리 응답의 `replayed`는 `false`, 기존 결과를 반환한 재시도 응답의 `replayed`는 `true`다.
- 동시 요청이 UNIQUE 제약에서 경합하면 저장에 성공한 최초 결과를 조회해 반환한다.

## 교사 조회와 수정

- 담당 교사만 자신에게 속한 아동의 이야기, 분기 소제목·질문·선택지, 확정된 선택, 본문과 이미지를 조회할 수 있다.
- 교사는 생성됐지만 아동이 아직 읽지 않은 페이지의 분기 소제목, 본문, 선택지 3개와 이미지만 수정할 수 있다.
- 이미지 수정은 교사의 직접 업로드와 Gemini 재생성을 모두 제공하며, 두 방식 모두 새 revision으로 저장한다.
- 이미 읽은 페이지, 아동이 확정한 선택과 이야기 진행률은 수정할 수 없다.
- 교사 수정은 revision 기반 낙관적 잠금으로 처리하고 충돌하면 `409 Conflict`, 형식·분량·안전 규칙 위반이면 `422 Unprocessable Entity`를 반환한다.
- 수정된 본문·선택지·소제목은 이후 이야기 생성의 확정 이력으로 사용한다. 이미지 수정은 이야기 텍스트 맥락을 변경하지 않는다.
- 교사 수정 이력에는 수정 주체, 시각, 대상과 변경 전후 revision을 남기며 아동에게 아직 공개되지 않은 내용만 새 revision으로 제공한다.
