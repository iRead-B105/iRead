# 아동 App 수행 피드백과 재시도

- 상태: accepted
- 결정일: 2026-07-28
- 관련 기능: `TR-COM-03`~`TR-COM-04`, `TR-REC-07`~`TR-REC-09`, `TR-SEL-04`~`TR-SEL-05`, `TE-COM-02`~`TE-COM-04`, `TE-REC-07`~`TE-REC-08`, `TE-SEL-04`, `ST-BRANCH-01`~`ST-BRANCH-05`

## 책임 경계

- 아동 App은 Backend가 제공한 문항을 표시하고 선택·녹음·시선 같은 실제 사용자 입력과 문항 위치만 전달한다.
- Backend는 저장된 생성 문항에서 기대 답을 조회하고 정답 판정, STT·발음 분석, 점수 계산, 특징 태깅과 프로필 갱신을 수행한다.
- 아동 App은 `recognizedText`, 기대 발음, 정답 여부, 점수와 특징 코드를 계산하거나 신뢰 가능한 입력값으로 전달하지 않는다.
- 기술적 분석 실패는 아동의 오답으로 간주하지 않는다.

## 훈련

- 제출 직후 정답 여부, 오류 위치와 다음 행동을 안내한다.
- 평가에 성공한 시도는 문항당 최대 3회다. 네트워크 재전송과 STT·발음 분석 실패는 횟수에 포함하지 않는다.
- 1회차 오답이면 2회차에 정답을 직접 노출하지 않는 힌트를 제공한다.
- 2회차 오답이면 동일 문항의 3회차를 허용하며 기존 힌트를 유지한다.
- 3회차 오답이면 정답을 제공하고 문항을 종료한다.
- 1~3회차 중 정답이면 해당 시도를 최종 시도로 확정하고 문항을 종료한다.
- 같은 문항·분석 대상·토큰의 최신 평가 시도만 `word_attempt_logs.is_final=true`이며 이전 평가 시도는 `false`로 변경한다.
- 최종 시도만 학생 특징 프로필의 근거로 사용한다.
- 훈련 완료 요청에는 App이 집계한 결과나 완료 시각을 포함하지 않는다. Backend가 저장된 최종 시도를 집계하고 서버 시각으로 완료 처리한다.
- 아동 완료 화면에는 정확도 대신 완료 상태, 칭찬 메시지와 다음 이동만 제공한다.

## 검사

- 문항당 최초 평가 성공 시도 한 번만 인정한다. 네트워크 재전송과 기술적 분석 실패는 시도로 계산하지 않는다.
- 문항 제출 후 아동에게 정답·오답, 점수, 인식 문장과 특징 분석을 제공하지 않고 저장 완료와 전체 진행률만 제공한다.
- 검사 완료 후 아동에게 완료 안내와 간단한 칭찬 화면만 제공한다.
- 상세 정답·오답, 점수와 특징 분석은 교수자 앱에서만 제공한다.
- 검사 문항 저장과 진행률 갱신은 문항 제출 응답에서 끝내며 별도의 문항 완료·누적 결과 저장 API를 사용하지 않는다.
- 검사 전체 완료 요청은 `testId`만 받고 Backend가 모든 문항의 제출 여부와 서버 완료 시각을 결정한다.

## 공통 음성 분석 실패

- STT 또는 발음 분석을 완료하지 못한 입력은 최종 시도와 점수로 저장하지 않는다.
- 실패한 입력은 프로필과 보고서 집계에서 제외한다.
- 현재 문항을 유지하고 다시 녹음하도록 안내한다.
- 음성 원본은 성공·실패와 관계없이 처리 직후 폐기한다.

## 이야기 나라

- 점수와 정답 여부를 사용하지 않는다.
- 분기점에는 AI가 생성한 질문과 서로 다른 버튼 선택지 3개를 함께 제공한다.
- STT 성공 시 인식 문장을 아동에게 먼저 보여주고 확인을 받은 뒤 다음 이야기를 생성하며, 아동은 버튼 선택으로도 바로 확정할 수 있다.
- 인식 문장을 거절하거나 STT에 실패하면 같은 분기에서 다시 녹음한다.
- 최초 녹음과 재시도 2회까지 총 3회의 음성 입력을 허용한다.
- 세 번 모두 실패하거나 거절하면 현재 분기점에 이미 제공된 AI 선택지 3개 중 하나를 선택하도록 안내한다.
- 아동이 인식 문장을 확인하거나 대체 선택지를 선택한 경우에만 최종 선택 텍스트와 다음 장면을 저장한다.
- STT 중간 결과, 거절한 문장과 실패한 음성은 `story_choices`에 저장하지 않는다.
- 최종 확정 후에는 점수 없이 다음 이야기만 제공한다.

## 오류와 멱등성

- 훈련·검사 시작 요청이 네트워크에서 재전송되어 대상이 이미 `IN_PROGRESS`이면 최초 `startedAt`과 현재 상태를 그대로 `200 OK`로 반환하고 시작 이벤트를 다시 발행하지 않는다.
- 완료된 훈련·검사에 같은 완료 요청이 재전송되면 결과를 재계산하거나 완료 이벤트를 다시 발행하지 않고 저장된 식별자, 상태와 `completedAt`을 `200 OK`로 반환한다.
- 훈련·검사 세션 초기화는 완료 전 상태만 허용하고 완료 데이터에는 `409 Conflict`를 반환한다.
- 같은 제출의 네트워크 재전송은 멱등성 키로 식별하고 재시도 횟수를 증가시키지 않는다.
- 비음성 제출의 `submissionId`와 확정 응답은 기존 `trainings.result` 또는 `tests.result`의 제출 목록에 저장한다. 별도 컬럼은 추가하지 않는다.
- Backend는 해당 훈련·검사 행을 잠근 트랜잭션에서 `submissionId`를 먼저 확인하고, 이미 처리한 값이면 저장된 응답을 그대로 반환한다.
- 분석 서비스의 타임아웃·잘못된 응답은 재시도 가능한 오류로 반환한다.
- 이미 확정된 검사 응답 또는 이야기 분기를 다른 값으로 덮어쓰지 않는다.
- 이야기 분기는 `story_line_id`별 최초 결과를 재사용하지만 신규 이야기 세션 생성은 호출마다 별도 `storyId`를 만드는 비멱등 요청이다. 생성 응답이 불확실하면 자동 재전송하지 않고 책장·이어하기 조회로 생성 여부를 확인한다.
- 훈련에서 새 평가 시도를 저장할 때 이전 `is_final` 해제와 새 `is_final` 설정을 하나의 트랜잭션으로 처리한다.

## 후속 계약

- 훈련·검사 문항 조회는 [공통 문항 JSON Schema](../../../contracts/json/app-learning-question.schema.json)의 `questionType`, `responseType`, `content`와 선택적 `requiredInputs`만 App 표시 영역으로 반환한다.
- 검사는 `test_datas.generated_data`를 그대로 반환하지 않고 훈련과 같은 App 문항 계약으로 변환한다.
- 정답, 기대 발음, 분석 대상과 특징 코드는 문항 조회 응답에서 제외한다.
- 비음성 훈련·검사 요청은 [공통 제출 JSON Schema](../../../contracts/json/app-learning-submission.schema.json)의 `submissionId`, `responseType`, `response`만 사용한다. 검사 요청은 현재 경로에 `testId`가 없으므로 이 공통 객체를 `submission`으로 감싸고 `testId`를 함께 보낸다.
- `responseType`은 `TRACE`, `SINGLE_CHOICE`, `ORDERING`, `COMPONENT_BUILD`, `TEXT_INPUT` 중 하나이며 Backend가 문항 조회 결과와 일치하는지 검증한다.
- 음성 요청은 별도의 녹음 API와 `multipart/form-data`를 사용한다.
- 비음성 훈련 응답은 [훈련 피드백 JSON Schema](../../../contracts/json/training-feedback.schema.json)의 `TRAINING_FEEDBACK`, 비음성 검사 응답은 [검사 진행률 JSON Schema](../../../contracts/json/test-progress.schema.json)의 `TEST_PROGRESS`를 사용한다.
- 이야기 응답은 후속 계약에서 `STORY_RECOGNITION_CONFIRMATION`, `STORY_FALLBACK_OPTIONS`, `STORY_NEXT_SCENE`을 구분한다.

## Backend 구현 경계

- 비음성 선택·순서·글자 구성·직접 입력은 저장된 생성 문항의 `answer`와 Backend에서 비교한다. App이 보낸 정답 여부와 점수는 받지 않는다.
- `[ASSUMPTION]` 필기 품질 분석 모델이 연결되기 전 데모의 `TRACE` 제출은 캔버스, 획과 좌표의 구조·완전성 검증을 통과하면 정답으로 처리한다. 실제 획순·형태 판정은 동일 평가 경계의 후속 adapter로 교체한다.
- 비음성 제출 상세와 점수는 `trainings.result.submissions` 또는 `tests.result.submissions`에 내부 근거로 저장하되 아동 응답에서는 제외한다.
- 검사 문항별 완료 API는 사용하지 않는다. 최초로 수락된 문항 제출이 해당 문항의 완료를 의미한다.
