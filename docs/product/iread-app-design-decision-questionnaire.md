# 아이리드 앱 디자인 다듬기 질문서

- 상태: draft
- 적용 대상: `services/frontend-app`
- 조사 기준일: 2026-07-30
- 관련 기준: [아이리드 앱 디자인 가이드](iread-app-design-guide.md)

## 1. 이 질문서의 목적

아이리드 아동용 UI는 이미 80% 이상 만들어져 있다. 전면 재설계가 아니라, 현재 장점을 유지하면서 완성도를 좌우하는 나머지 부분을 같은 시각으로 다듬는 것이 목적이다.

이번에 결정할 범위는 다음 여섯 가지뿐이다.

1. 화면 간 디자인 통일성 강화
2. 아동용 디자인 강화
3. 미완성된 이야기 캐릭터 배치 기능 설계
4. 기존·신규 리소스 정리와 화풍 통일
5. 리소스와 UI의 배치·화면 비율 정리
6. 아동의 흥미와 학습 효율을 높이는 피드백 인터랙션 설계

개발 방식에 사실상 정답이 있는 항목, 회사 규모의 승인 체계, 담당자 조직, CDN·캐시의 세부 수치 같은 내용은 이 질문서에서 묻지 않는다.

## 2. 이미 확정된 전제

다음 내용은 다시 선택하지 않는다.

- 현재 화면 구조와 시각 방향의 80% 이상을 유지한다.
- 별, 구름, 꽃, 카드 프레임, 캐릭터, 아이콘 같은 시각 오브젝트는 정식 리소스로 만든다.
- CSS 도형, 이모지, 텍스트 기호와 화면별 inline SVG로 시각 리소스를 대신하지 않는다.
- 같은 역할은 같은 공통 리소스와 공통 컴포넌트를 사용한다.
- 글을 충분히 읽지 못하는 아동도 아이콘, 소리와 화면 흐름으로 조작할 수 있어야 한다.
- 개발용 원본과 후보안은 `design-resources`에 두고, 앱에는 승인된 최종 리소스만 넣는다.
- 런타임 이미지는 실제 표시 크기에 맞게 최적화하고, 필요한 화면과 상태에서만 불러온다.
- 에셋 포맷·압축·캐시·빌드 검사는 사용자 취향 질문이 아니라 구현 기본값으로 처리한다.

## 3. 답변 방법

각 질문에서 A, B, C 중 하나만 체크한다.

- `A · BEST`: 현재 UI와 요청을 함께 고려한 권장안
- `B`: 조금 더 화려하거나 변화가 큰 대안
- `C`: 변화가 적거나 단순한 대안
- `메모`: 선택지를 조금 바꾸고 싶을 때만 작성

처음에는 전체 `A · BEST`를 기본 초안으로 보고, 마음에 들지 않는 질문만 B 또는 C로 바꾸면 된다.

  - [ ] **B** — 모든 버튼을 둥근 사각형으로 통일한다.
  - [ ] **C** — 화면마다 현재 버튼 모양을 유지한다.
  - 메모:A

- [ ] `UNI-005` 테두리와 그림자는 어느 정도로 정리할까?

  - [ ] **B** — 장난감 느낌을 위해 이중 테두리와 두꺼운 그림자를 적극 사용한다.
  - [ ] **C** — 그림자를 거의 없애고 평면적으로 정리한다.

- [ ] `UNI-007` 공통 아이콘의 스타일은 어떻게 맞출까?
  - [ ] **A · BEST** — 둥글고 두꺼운 플랫 아이콘, 동일한 외곽선과 동일한 입체감으로 새 세트를 만든다.
  - [ ] **B** — 아이콘마다 작은 별·하트·반짝임 장식을 추가한다.
  - [ ] **C** — 현재 아이콘을 유지하고 없는 것만 비슷하게 추가한다.
  - 메모:A

- [ ] `UNI-008` 화면별 개성을 어디까지 허용할까?
  - [ ] **A · BEST** — 공통 프레임과 조작부는 같게 두고 배경·캐릭터·과제 표현만 화면별로 바꾼다.
  - [ ] **B** — 이야기, 성장, 훈련 영역이 서로 다른 앱처럼 보여도 괜찮다.
  - [ ] **C** — 모든 영역을 거의 같은 배경과 패널로 통일한다.
  - 메모:A

- [ ] `UNI-009` 현재 가장 먼저 통일할 요소는 무엇인가?
  - [ ] **A · BEST** — 선택 카드, 듣기 버튼, 뒤로가기, 진행도, 피드백
  - [ ] **B** — 배경, 헤더, 캐릭터와 장식
  - [ ] **C** — 화면별 제목과 글자 크기
  - 메모:A B C 다 순차적으로 해야함

### B. 아동용 디자인 강화

- [ ] `KID-001` 글을 아직 잘 읽지 못하는 아동을 어느 정도 기준으로 삼을까?
  - [ ] **A · BEST** — 글을 읽지 않아도 핵심 행동을 아이콘과 소리로 이해할 수 있게 한다.
  - [ ] **B** — 아이콘과 짧은 문구를 항상 함께 보여준다.
  - [ ] **C** — 현재처럼 문구 중심 안내를 유지한다.
  - 메모: A + B 기본적으로 글없이도 대부분 수행 가능 하도록 하되, 이야기 나라와 같이 아주 기본적인 수준의 글읽기가 탑제 되어야만 가능한 서비스나 기본 훈련이나 테스트에도 설명을 위한 최소한의 글은 필요할수 있으니 A 기반이되 B가 있기는 한느낌 근데 버튼 - 제목 정도로만 가야지 예를들어 볼륨버튼 - 제목: 소리를 키워요 - 설명: 바를 조절해서 소리를 키울 수 있어요 이런식으로 제목-설명 처럼 글이 2줄이상 되면 절대 안됨 A처럼 아이콘으로만 표현가능 하되 명료한 제목 하나 정도는 필요에 따라 가능

- [ ] `KID-002` 한 화면에 보여주는 정보량은 어느 정도가 좋은가?
  - [ ] **A · BEST** — 지금 해야 할 한 가지 과제와 필요한 조작만 크게 보여준다.
  - [ ] **B** — 다음 단계와 보상 정보도 함께 보여준다.
  - [ ] **C** — 현재 정보량을 유지한다.
  - 메모: A

- [ ] `KID-003` 클릭·터치·시선 선택 영역은 얼마나 크게 만들까?
  - [ ] **A · BEST** — 보이는 리소스보다 실제 선택 영역을 넉넉하게 만들고 주요 선택지는 크게 유지한다.
  - [ ] **B** — 화면을 풍성하게 쓰기 위해 선택지를 조금 작게 만든다.
  - [ ] **C** — 현재 크기를 유지한다.
  - 메모: A

- [ ] `KID-004` 장식은 어느 정도가 적당한가?
  - [ ] **A · BEST** — 화면 가장자리와 빈 배경에만 사용하고 문제·버튼 주변은 비운다.
  - [ ] **B** — 카드와 버튼 주변에도 반짝임·별·꽃을 적극 사용한다.
  - [ ] **C** — 대부분의 장식을 제거한다.
  - 메모: A

- [ ] `KID-005` 아동용 색감은 어떻게 조절할까?
  - [ ] **A · BEST** — 배경은 밝고 따뜻하게, 조작부는 파스텔로, 중요한 학습 글자만 선명하게 만든다.
  - [ ] **B** — 배경과 조작부 모두 선명하고 높은 채도로 만든다.
  - [ ] **C** — 전체 화면을 저채도 파스텔로 만든다.
  - 메모: 고채도 플랫 백터 일러스트로 한다, 하지만 학습 화면 내부와 외부가 구별은 되어야한다

- [ ] `KID-006` 캐릭터는 화면에 얼마나 자주 등장할까?
  - [ ] **A · BEST** — 시작·성공·도움·완료처럼 감정적으로 필요한 순간에만 등장한다.
  - [ ] **B** — 대부분의 학습 화면에서 안내 캐릭터가 계속 동행한다.
  - [ ] **C** — 이야기와 완료 화면에서만 등장한다.
  - 메모: B 대부분의 학습 화면에서 안내 캐릭터가 동행 하고 시작 성공 도움 완료시에 피드백 인터랙션을 제공한다.

- [ ] `KID-007` 오답 표현은 어떻게 할까?
  - [ ] **A · BEST** — 짧고 부드러운 흔들림과 다시 시도 안내를 주고 강한 빨강·경고음은 피한다.
  - [ ] **B** — 오답을 분명히 알 수 있게 빨강과 효과음을 강하게 사용한다.
  - [ ] **C** — 오답 표시 없이 다시 선택할 기회만 준다.
  - 메모: A

- [ ] `KID-008` 움직이는 효과의 강도는 어느 정도가 좋을까?
  - [ ] **A · BEST** — 행동 직후 0.3~0.8초의 짧은 반응만 사용하고 계속 움직이는 장식은 최소화한다.
  - [ ] **B** — 캐릭터와 장식이 화면에서 계속 작게 움직인다.
  - [ ] **C** — 움직임을 거의 사용하지 않는다.
  - 메모: A

- [ ] `KID-009` 안내 문장의 말투는 어떻게 통일할까?
  - [ ] **A · BEST** — 짧고 친근한 `~해봐요` 말투로 한 번에 한 행동만 말한다.
  - [ ] **B** — 더 장난스럽고 감탄사가 많은 말투를 사용한다.
  - [ ] **C** — 설명이 명확한 `~하세요` 말투를 사용한다.
  - 메모: B 약간 반말로 해봐! 잘했어! 대단해! 이런느낌

- [ ] `KID-010` 아동용 화면에서 피해야 할 느낌은 무엇인가?
  - [ ] **A · BEST** — 관리자 도구 같은 표·회색 버튼·작은 글자·기술 용어를 모두 피한다.
  - [ ] **B** — 설정과 상태 화면에는 일부 성인용 UI를 허용한다.
  - [ ] **C** — 기능 전달이 명확하면 성인용 UI를 사용해도 괜찮다.
  - 메모: A (아이트래커와, 마이크 설정 정도는 약간의 어려운 용어도 허용)

### C. 이야기 캐릭터 배치 기능

현재 구현에는 이야기 친구 해금, 목록 조회와 수집 모달이 있다. 캐릭터를 실제 공간에 놓고 다시 배치하는 흐름은 완성되지 않았다.

- [ ] `CHR-001` 해금한 이야기 캐릭터는 어디에 놓을까?
  - [ ] **A · BEST** — 이야기 친구 전용 `이야기 마을` 공간에 놓는다.
  - [ ] **B** — 나의 성장 정원에 함께 놓는다.
  - [ ] **C** — 메인 섬 지도 주변에 놓는다.
  - 메모: B

- [ ] `CHR-002` 이야기 마을에는 어디에서 들어갈까?
  - [ ] **A · BEST** — `이야기 친구들` 버튼에서 수집 목록과 마을을 함께 연다.
  - [ ] **B** — 메인 섬에 이야기 마을 지역을 새로 만든다.
  - [ ] **C** — 이야기 완료 화면에서만 들어갈 수 있게 한다.
  - 메모: 나의 성장 정원에서 이야기 친구들을 볼 수 있음

- [ ] `CHR-003` 새 캐릭터를 얻었을 때 흐름은 어떻게 할까?
  - [ ] **A · BEST** — 짧은 획득 축하 후 `지금 놓기`와 `나중에 놓기`를 아이콘으로 제공한다.
  - [ ] **B** — 획득 즉시 마을의 빈자리에 자동 배치한다.
  - [ ] **C** — 수집 목록에만 추가하고 별도 배치 안내는 하지 않는다.
  - 메모: A

- [ ] `CHR-004` 캐릭터 배치는 어떤 방식이 좋을까?
  - [ ] **A · BEST** — 배경에 정해진 큰 슬롯을 두고 캐릭터를 슬롯 사이로 옮긴다.
  - [ ] **B** — 원하는 위치에 자유롭게 드래그해 놓는다.
  - [ ] **C** — 사용자는 배치하지 않고 정해진 위치에 자동으로 보인다.
  - 메모: A

- [ ] `CHR-005` 시선 입력으로도 캐릭터를 배치하게 할까?

## 5. 질문 답변 후 만들 결과물

답변이 끝나면 다음 결과물만 만든다.

1. 앱 전체에서 유지할 디자인 원칙 8~12개

3. 현재 리소스의 `유지/다듬기/다시 만들기/미사용` 목록
4. 새로 만들어야 할 공통·화면별 리소스 목록
5. `1920×1080`, `1280×720` 화면별 배치 기준
6. 이야기 캐릭터 획득·배치·상호작용 화면 흐름
