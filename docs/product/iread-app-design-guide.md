# 아이리드 앱 디자인 가이드

> 적용 범위: `services/frontend-app`
>
> 기준 버전: 현재 Vue 3 아동용 앱
>
> 최종 배포 환경: Windows EXE 전체화면

## 1. 디자인 방향

아이리드는 난독 아동이 화면을 오래 해석하지 않아도 바로 다음 행동을 이해할 수 있는 학습 서비스다.

모든 아동용 화면은 다음 네 가지 원칙을 우선한다.

1. **선명한 고채도 플랫 벡터**

   큰 색면과 단순한 형태를 사용하고 수채화, 사진풍, 사실적 재질, AI 특유의 뭉개진 형태를 사용하지 않는다.

2. **읽어야 할 정보 최소화**

   문제 해결에 필요하지 않은 분류명, 단계명, 점수, 분석값과 설명 문장은 숨긴다.

3. **한 화면, 한 행동**

   아동이 지금 해야 할 행동을 하나만 강하게 보여 준다.

4. **시선·음성 중심 상호작용**

   아이트래커와 STT 상태를 명확히 전달하고 마우스·터치 대체 입력도 같은 흐름을 제공한다.

### 1.1 2026-07-30 확정 방향

- 기존 Vue 화면과 흐름의 80% 이상을 유지하고 공통 카드, 버튼, 간격, 리소스와 피드백을 중심으로 다듬는다.
- 전체 인상은 동화책 콘셉트의 고채도 플랫 벡터다. 둥글고 단단한 실루엣과 큰 선택 영역으로 아동이 쉽게 구분하고 누를 수 있게 한다.
- 학습 겉배경은 선명하게 유지하고, 안쪽 문제 패널은 크림·연노랑 표면으로 분리해 학습 자극이 먼저 보이게 한다.
- 핵심 행동은 아이콘만으로도 이해할 수 있어야 한다. 필요한 글자는 한 줄 제목까지만 허용하며 제목과 설명을 두 줄 이상 쌓지 않는다.
- 안내 토끼는 대부분의 훈련 화면에 동행하고 시작, 정답, 반복 실패, 도움과 완료 상황에서 짧게 반응한다.
- 아동 안내와 칭찬은 `해봐!`, `잘했어!`, `대단해!`처럼 짧고 친근한 반말을 사용한다.
- 이야기 친구는 별도 마을이 아니라 `나의 성장` 정원의 고정 슬롯에 최대 4명까지 배치한다.
- 중간 연속 정답 보상은 사용하지 않는다. 5문제 훈련을 한 번도 틀리지 않고 모두 완료했을 때만 일반 완료와 다른 특별 완료 화면을 제공한다.

## 2. 실행 환경과 기준 해상도

### 2.1 전체화면 EXE

- 최종 앱은 브라우저 탭이 아니라 **Windows EXE 전체화면**을 기준으로 한다.
- 브라우저 주소창, 탭, OS 작업 표시줄이 없는 노트북 F11 전체화면 안에 `1920 × 1200` 고정 논리 캔버스를 둔다.
- 학습자 앱은 반응형 재배치 화면이 아니다. 실제 화면 크기에 맞춰 논리 캔버스 전체를 하나의 배율로 확대·축소한다.
- 메인, 학습, 독서 화면은 세로 스크롤 없이 한 화면 안에서 핵심 과제를 완료하도록 구성한다.
- 뒤로 가기나 홈 이동은 브라우저 UI에 의존하지 않고 서비스 헤더와 화면 버튼으로 제공한다.
- 종료는 헤더 오른쪽의 `나가기` 버튼으로 제공한다.

### 2.2 해상도 기준

| 구분 | 해상도 | 용도 |
| --- | ---: | --- |
| 디자인 기준 | `1920 × 1200` | 현재 개발 노트북 F11과 같은 16:10 전체화면 QA 기준 |
| 최소 검증 | `1280 × 800` | 작은 16:10 노트북과 태블릿 |
| 일반 검증 | `1680 × 1050` | 학교·가정용 16:10 노트북 |
| 고해상도 검증 | `2880 × 1800` | 현재 개발 노트북의 실제 패널 해상도 |

- 기본 화면 비율은 현재 개발 노트북 F11 전체화면과 같은 `16:10`이다.
- `1280 × 800`, `1920 × 1200`, `2880 × 1800`처럼 비율이 같은 화면에서는 글자, 카드, 이미지, 간격과 헤더가 모두 같은 비율로 변해야 한다.
- 화면이 작아져도 글자만 줄바꿈하거나 카드 순서가 바뀌지 않는다. 다른 화면비에서는 전체 장면을 잘리지 않게 맞추고 남는 영역을 레터박스로 처리한다.
- 중요한 글자, 버튼과 캐릭터는 고정 캔버스 가장자리에서 최소 `3cqw`, 위아래 최소 `3cqh` 안쪽의 안전 영역에 둔다.
- 배경은 `cover`, 독립 캐릭터·아이콘·지도는 `contain`을 기본값으로 사용한다.
- 배경이 잘릴 때 중요한 사물은 중앙 `80% × 80%` 안에 남아야 한다.
- 내부 크기 계산은 고정 논리 캔버스 또는 해당 캔버스의 `cqw`, `cqh`, `cqmin`을 사용한다. 브라우저 실제 viewport의 `vw`, `vh`, `dvh`로 학습자 화면을 다시 배치하지 않는다.
- 아동이 누르는 조작 요소는 최소 `52 × 52px`, 주요 행동 버튼은 높이 `60~72px`를 권장한다.

### 2.3 현재 레이아웃 기준

- 헤더 높이: `clamp(96px, 13.3cqh, 116px)`
- 최대 콘텐츠 폭: `1440px`
- 독서 콘텐츠 기준 폭: `1080px`
- 페이지 좌우 여백: `clamp(24px, 4cqw, 64px)`
- 헤더는 페이지를 아래로 밀지 않는 오버레이 구조다.
- 페이지 배경은 화면 최상단부터 채우고, 실제 콘텐츠만 헤더 아래 안전 영역에 배치한다.

## 3. 시각 언어

### 3.1 일러스트 스타일

모든 신규 아동용 에셋은 아래 기준으로 제작한다.

- 고채도 플랫 벡터 일러스트
- 둥글고 단순한 실루엣
- 아웃라인이 없거나 매우 제한적인 내부선
- 한 오브젝트당 주색 1개와 명암색 1~2개
- 명암은 부드러운 수채 번짐이 아니라 구분 가능한 큰 색면
- 그림자는 짧고 부드러운 바닥 그림자 또는 한 단계의 셀 셰이딩
- 눈, 손가락, 책장, 블록 모서리처럼 의미가 있는 형태는 서로 겹치거나 뭉개지지 않게 제작
- 같은 캐릭터는 머리 비율, 눈 위치, 손발 크기와 대표 색을 상태별로 유지

### 3.2 사용하지 않는 스타일

- 수채화, 크레용, 유화, 종이 질감 중심 스타일
- 사진과 반실사 3D 렌더
- 과도한 광택, 유리 재질, 복잡한 그라데이션
- 두꺼운 검정 외곽선
- 저채도 파스텔만으로 구성된 흐릿한 화면
- 실제 기능이 없는 작은 배지와 장식 텍스트
- 서로 다른 화풍의 배경과 캐릭터를 한 화면에 혼합

### 3.3 리소스 우선 원칙

아이리드의 시각적 오브젝트는 CSS 도형이나 텍스트 기호로 그리지 않고 정식 이미지 리소스로 제작한다.

리소스로 제작해야 하는 대상은 다음과 같다.

- 별, 구름, 꽃, 새싹, 광선, 음표, 파형처럼 화면에 보이는 장식
- 스피커, 다시 듣기, 마이크, 눈, 잠금, 체크, 화살표, 드래그 손잡이처럼 의미를 전달하는 아이콘
- 캐릭터, 동물, 사물, 지도, 발판, 간판, 배지와 학습용 그림
- 카드의 고유 실루엣·재질·장식처럼 아이리드의 시각 언어를 만드는 그래픽
- 반복 사용하는 로딩·성공·힌트 애니메이션의 시각 오브젝트

다음 표현은 최종 UI의 시각 리소스로 사용하지 않는다.

- `border-radius`, pseudo-element와 box-shadow를 조합해 캐릭터·구름·별·꽃·사물·아이콘을 그리는 CSS 도형
- `●`, `→`, `✦`, `★`, `♫`, `⠿` 같은 유니코드 문자와 이모지를 아이콘 또는 장식으로 사용하는 방식
- Vue 템플릿의 inline SVG markup으로 화면별 아이콘과 장식을 직접 그리는 방식
- 기능을 설명하기 위한 임시 CSS 그림과 브라우저 기본 기호
- 한 화면에서만 쓰고 버리는 화풍이 다른 임시 이미지

CSS는 다음 역할만 담당한다.

- 레이아웃, 정렬, 크기, 간격과 반응형 배치
- 타이포그래피와 HTML 텍스트
- 패널·버튼·입력 영역의 기본 표면색, 테두리, 모서리와 공통 그림자
- hover, focus, active, selected, disabled 같은 상태 전환
- 접근성 포커스 링, 진행 게이지의 채움과 콘텐츠 마스킹
- 정식 리소스의 위치, 크기, 투명도와 제한된 상태별 색상 처리

같은 그래픽의 노랑·민트·보라 variant는 런타임 CSS 필터로 만들지 않는다. 승인 원본에서 동일 캔버스와 알파를 유지한 실제 색상별 파일을 생성하고 Vue·CSS는 해당 파일을 선택만 한다.

같은 역할의 리소스는 공통 컴포넌트가 같은 파일을 사용한다. 화면별 CSS에서 유사한 도형을 다시 만들지 않는다. 필요한 리소스가 없으면 임시 CSS 도형으로 대체하지 않고 `리소스 추가 필요` 상태를 유지한 뒤, 디자인 가이드에 맞는 리소스를 제작·검수·등록한다.

### 3.4 이미지 생성 프롬프트 기준

신규 에셋 생성 시 다음 표현을 기본 프롬프트에 포함한다.

```text
Korean children's learning app asset,
high-saturation flat vector illustration,
clean rounded geometric shapes,
outline-free or minimal internal lines,
two-step cel shading,
crisp separated objects,
no watercolor, no photorealism, no painterly texture,
transparent background with real alpha channel,
no text, no watermark
```

배경 이미지는 마지막 두 줄을 다음처럼 바꾼다.

```text
16:9 full-screen background, 1920x1080,
important subjects inside the central safe area,
no text, no UI, no watermark
```

## 4. 알파 채널 규칙

### 4.1 알파 채널이 필수인 에셋

- 캐릭터와 캐릭터 포즈
- 지도 위 호버 교체 레이어
- 아이콘과 학습 카드 그림
- 마을 장식, 블록, 꽃, 책, 가구
- 말풍선 장식과 이펙트
- 로고와 화면 위에 겹쳐 쓰는 오브젝트

위 에셋은 **진짜 RGBA 알파 채널**을 가진 PNG 또는 무손실 WebP로 저장한다.

### 4.2 불투명 이미지가 적절한 경우

- `1920 × 1080` 전체화면 배경
- 학습 화면 겉배경과 속배경
- 이야기 AI 생성 삽화
- 정원과 바다처럼 화면 전체를 채우는 장면

배경은 투명할 필요가 없으며 RGB 이미지로 저장해도 된다. 단, 배경과 UI를 한 이미지에 합치지 않는다.

### 4.3 알파 QA

- 체크무늬를 이미지에 직접 그려 넣지 않는다.
- 네 모서리를 투명 배경 위에서 확인한다.
- 흰색 또는 검정색 테두리 잔상이 없어야 한다.
- 오브젝트 바깥의 불필요한 투명 여백은 제거하되 그림자와 동작 범위는 보존한다.
- 동일 상태 교체용 이미지는 캔버스 크기와 기준점을 완전히 동일하게 유지한다.
- 가짜 알파 이미지가 들어오면 배경 제거 후 가장자리 색 번짐을 검사한다.

### 5.4 색상 사용 규칙

- 한 화면의 강한 강조색은 기본 1개, 보조 1개까지만 사용한다.
- 긴 본문은 남색과 크림·연노랑 배경 조합을 사용한다.
- 색만으로 상태를 전달하지 않고 아이콘, 형태 또는 짧은 문구를 함께 사용한다.
- 오류는 화면 전체를 빨갛게 만들지 않고 해당 카드와 짧은 피드백에만 사용한다.
- 흰 글자는 충분히 진한 파랑·주황·초록·보라 배경 위에서만 사용한다.
- 신규 색이 필요하면 먼저 `services/frontend-app/src/styles/common/tokens.css`에 의미 기반 토큰을 추가한다.
- 3지선다 카드는 노랑, 민트, 보라 순서를 유지한다. 세 색 모두 현재 팔레트와 같은 고채도 플랫 벡터 계열을 사용하되 형광펜처럼 눈부신 채도와 흐릿한 저채도는 피한다.
- 학습 카드의 중앙 쓰기 면은 크림색으로 유지하고 프레임·점선·상태 테두리만 위치별 색상을 사용한다.

## 6. 타이포그래피

### 6.1 글꼴 역할

- 학습 낱말, 문장, 이야기 본문: `PeachMarket`
- 메뉴, 버튼, 제목: `Arial Rounded MT Bold`, `Noto Sans KR`
- 교수자 UI는 이 문서의 아동용 글꼴 규칙을 적용하지 않는다.

### 6.2 기준 크기

| 용도 | 권장 크기 |
| --- | --- |
| 이야기·집중 읽기 본문 | `38~60px` |
| 페이지 제목 | `38~60px` |
| 카드 제목 | `26~38px` |
| 주요 버튼 | `22~28px` |
| 일반 안내 | `18~24px` |
| 최소 보조 글자 | `16px` |

- 읽기 대상은 장식 글자보다 항상 크고 진해야 한다.
- 긴 문장은 한 줄을 지나치게 길게 만들지 않고 의미 단위로 줄바꿈한다.
- 자간을 과하게 좁히지 않으며 글자 뒤에 복잡한 그림이 있으면 밝은 반투명 보호 영역 또는 텍스트 그림자를 사용한다.
- 학습 화면에서 작은 캡션으로 정보 계층을 만들지 않는다.
- 주요 선택 카드와 큰 행동 버튼에는 행동 이름만 크고 명확하게 표시한다.
- 행동 이름 아래에 작은 글씨로 같은 뜻의 세부 설명이나 보조 문구를 추가하지 않는다.
- 설명 없이는 의미가 불분명한 경우 작은 캡션을 붙이지 말고 행동 이름 자체를 아동이 바로 이해할 수 있는 표현으로 고친다.
- 꼭 필요한 안내는 선택 카드 내부가 아니라 화면의 공통 안내 영역이나 별도의 오류·도움말 UI로 제공한다.

## 7. 공통 UI 구조

### 7.1 헤더

현재 헤더 구조를 모든 아동용 주요 화면에서 유지한다.

- 왼쪽: 아동 프로필 정보
- 가운데: 책이 포함된 아이리드 메인 로고
- 가운데 로고 클릭: 홈 이동
- 오른쪽: 아이트래커 상태, 음성인식 상태, 나가기
- 마이크와 아이트래커 아이콘은 상태 표시와 함께 클릭하면 장치 확인·테스트·연결 제어 메뉴가 열리는 버튼이다.
- 장치의 자동 재연결 과정에서 `연결 중`과 `연결 안 됨`을 짧게 반복 노출하지 않는다. 내부 재시도 상태는 조용히 처리하고, 사용자 재연결 요청과 최종 연결 결과만 안정적으로 표시한다.
- 상태 변화로 메뉴의 너비·높이와 주요 요소 위치가 바뀌지 않도록 상태별 슬롯 크기를 고정한다.
- 연결이 해제된 동안에는 마우스 포인터가 시선과 같은 인터랙션을 수행한다.
- 연결됨은 초록색, 음성 인식 중은 파란색, 연결 없음·권한 거부는 빨간색 상태등으로 표시한다.
- 헤더 배경: 크림색 직선형 배경
- 헤더는 배경 화면 위에 겹치며 페이지 배경을 아래로 밀지 않는다.

아이트래커와 마이크는 다음 상태를 색과 아이콘으로 함께 표시한다.

- 회색 점: 상태 확인 중
- 초록 점: 연결 및 사용 가능
- 파랑 점: 현재 시선 수집 또는 음성 녹음 중
- 빨강 점: 연결되지 않음 또는 권한 없음

### 7.2 카드와 버튼

- 모서리 반경은 작은 요소 `12px`, 일반 카드 `18~28px`, 큰 카드 `32px`를 사용한다.
- 카드 그림자는 낮은 불투명도의 푸른 회색으로 통일한다.
- 주요 행동은 화면당 하나의 채워진 버튼으로 표시한다.
- 보조 행동은 흰색 또는 크림색 버튼으로 둔다.
- 듣기·다시 듣기·녹음처럼 반복되는 단일 행동은 아이콘만으로 조작하고 접근성 이름을 제공한다.
- 다음, 완료, 나가기처럼 흐름을 바꾸는 주요 행동은 아이콘과 한 줄 문구를 함께 제공할 수 있다.
- `hover`, `focus`, `active`, `disabled` 상태를 모두 구현한다.

## 8. 학습 화면 정보 최소화

### 8.1 남겨야 하는 정보

- 짧은 문제 지시문 하나
- 학습 대상
- 필요한 선택지 또는 조작 영역
- 현재 해야 할 주요 행동
- 즉각적인 성공·재시도 피드백
- 완료 후 다음 버튼

### 8.2 제거해야 하는 정보

- `오늘의 낱말`, `음운 인식`, `학습 유형` 같은 교사용 메타 정보
- 점수, 정확도, 발음 분석값과 실패 횟수
- 같은 의미의 반복 안내
- 항상 보이는 힌트 버튼
- 작은 진행 배지와 불필요한 페이지 번호
- 기술 용어와 장비 이름을 설명하는 긴 문장

### 8.3 과제 배치

- 선택지는 기본 3개를 사용한다.
- 큰 카드와 충분한 간격을 사용해 오선택을 줄인다.
- 드래그 과제는 출발 카드와 도착 빈칸을 시각적으로 분리한다.
- 오답 카드는 원래 위치로 돌아가고 정답 위치에 남지 않는다.
- 힌트는 버튼이 아니라 반복 실패 후 필요한 대상 하나만 반짝이는 방식으로 제공한다.
- 같은 문제에서 두 번 틀린 뒤 자동 시각 힌트를 제공하고 힌트 사용 여부는 화면에 표시하지 않는다.
- 저장 과정의 기술 문구는 보여주지 않고 로딩만 표시하며, 자동 재시도 실패 뒤에도 짧은 일반 오류만 사용한다.

## 9. 시선 추적·음성 상호작용

### 9.1 시선 표시

- 중심이 투명하고 외곽이 반투명한 원을 사용한다.
- 글자와 그림을 가리는 불투명 점을 사용하지 않는다.
- 이미 읽은 구간은 시선이 이탈해도 연하게 유지한다.
- 읽기 진행은 글자당 `0.1초`를 기본으로 하고 5글자 묶음은 `0.5초`처럼 글자 수에 비례한다.
- 3초 이상 이탈하면 다음 읽을 위치만 부드럽게 반짝인다.
- 시선 선택은 원형 진행 표시로 확정 전 체류 시간을 보여 준다.

### 9.2 STT와 TTS

- STT 화면에는 인식 점수와 파형 분석값을 노출하지 않는다.
- 문구는 `말해 봐요`, `한 번 더 읽어봐요`, `맞았어!`처럼 짧게 사용한다.
- TTS는 화면 문장을 길게 반복하지 않고 필요한 글자, 낱말 또는 힌트만 읽는다.
- 최초부터 정답 음성을 들려주지 않고 반복 실패 또는 시선 힌트 조건에서 제공한다.
- 정답 소리와 TTS의 재생 횟수는 제한하지 않으며 재생 횟수만 내부 학습 데이터로 남긴다.
- 음성 미감지·STT 오류는 다시 말하기로 안내하고 목표 발음 불일치만 오답으로 표현한다.
- 장비가 없는 개발 환경에서는 마우스와 클릭으로 동일 흐름을 확인할 수 있어야 한다.

## 10. 화면별 구성 기준

### 공통 프레임 규칙

- 글자 훈련과 이야기 나라는 서로 다른 기능이어도 같은 화면 문법을 사용한다.
- 최상위 콘텐츠 블록은 `연노랑 단일 프레임` 한 겹만 사용한다.
- 최상위 프레임은 흰색 반투명 `4px` 테두리, `32px` 모서리, 부드러운 파란 그림자를 기본으로 한다.
- 금색 선과 흰색 선을 겹친 이중·삼중 테두리, 안쪽 inset 테두리, 두꺼운 가짜 바닥 그림자는 사용하지 않는다.
- 프레임 내부의 이미지·과제 영역은 테두리를 반복하지 않고 옅은 배경 면과 `26px` 모서리로 구분한다.
- 실제로 누르는 카드만 연베이지 `3px` 테두리와 흰색에 가까운 면을 사용한다.
- 뒤로가기는 프레임 왼쪽 위의 연노랑 사각 버튼으로 통일한다.
- 공통 수치는 `tokens.css`의 `--learner-frame-*`, `--learner-inner-*`, `--learner-card-*` 토큰을 사용한다.

### 10.1 메인 지도

- 바다 배경은 `1920 × 1080` 전체화면으로 사용한다.
- 섬 기본 이미지와 각 호버 이미지는 동일한 `1536 × 1024` 캔버스와 기준점을 유지한다.
- 호버 시 해당 지역 이미지로 교체하고 약 `1.02`배 확대한다.
- 지역명은 지도 위에서 충분히 크고 흰 외곽을 가진 대분류 색으로 표시한다.

### 10.2 훈련 커리큘럼

- 학습 발판은 좌우로 이어지는 흐름을 사용한다.
- 현재, 완료, 잠김 발판은 동일한 크기와 위치 기준을 유지한다.
- 대분류 이름표는 지정된 주황·초록·파랑·보라를 사용한다.
- 훈련 이름은 발판에서 읽기 쉬운 흰색 굵은 글자로 표시한다.

### 10.3 실제 학습

- 겉배경은 선명한 학습 세계를 제공하되 장식 수를 제한한다.
- 속배경은 연노랑·아이보리 중심으로 글자 대비를 확보한다.
- 블록 안에 같은 모양의 블록을 중복해서 넣지 않는다.
- 과제, 선택지와 주요 버튼이 일렬로 길게 늘어서지 않도록 시각적 중심을 만든다.
- 학습 지시문은 `첫소리를 골라!`, `글자를 따라가봐!`처럼 친근한 반말로 행동 하나만 큰 글자로 안내한다.
- 예시 낱말을 다시 설명하는 긴 질문과 학습 이름·대분류 같은 메타 정보는 제거한다.
- 뒤로가기와 진행률은 연노랑 학습 블록 안쪽 상단에 함께 배치한다.
- 완료 화면은 학습명, 연습한 글자 목록, 완료 시각을 노출하지 않고 짧은 칭찬과 다음 행동만 제공한다.
- 기리 토끼는 문제 영역을 가리지 않는 가장자리에서 동행하며 기본, 정답, 재시도와 힌트 상태에 맞춰 짧은 말과 동작을 제공한다.

### 10.4 이야기 읽기

- 이야기 겉배경은 이야기 나라의 파랑·보라 계열을 사용한다.
- 속 삽화는 이야기마다 AI로 생성할 수 있으며 본문은 투명한 영역 위에 직접 배치한다.
- 한 페이지는 약 `50~60글자`, 큰 글자와 `2~3줄`을 기준으로 한다.
- 본문은 이미지 위쪽부터 시작한다.
- 페이지를 다 읽은 뒤에만 다음 버튼이 나타난다.
- 페이지 번호와 불필요한 진행 정보는 표시하지 않는다.
- 새로운 책 목록의 표지는 `story_templates.cover_image_url`을 사용하며 진행 중 장면을 임의로 표지로 대신 사용하지 않는다.
- 같은 원본으로 생성한 이야기는 새 제목·표지를 생성하지 않고 `원본 제목 + N번째 이야기`로 구분한다.
- 읽기가 3초 이상 멈추면 다음에 읽을 짧은 어절 묶음에 노랑 하이라이트를 표시하고 약한 확대·축소를 반복한다.
- 다시 읽기 시작하면 멈춘 묶음이 한 번 밝아진 뒤 그 위치부터 읽기 진행 표시를 이어간다.

### 10.5 이야기 선택 질문

- 현재 이야기 삽화를 어둡게 처리한 위에 중앙 모달을 표시한다.
- 질문과 자동 음성 듣기 상태만 남기며 정상 인식 문장 확인 단계 없이 바로 생성 대기로 전환한다.
- 선택지를 미리 제공하지 않고 아동의 STT 답변으로 다음 이야기를 생성한다.
- 질문 화면 진입 시 마이크를 자동으로 켜고, 글자 입력칸과 수동 마이크 시작 버튼은 제공하지 않는다.
- 질문 그림은 같은 장면의 고민하는 캐릭터 상태를 사용한다.
- 침묵이 길어지면 토끼가 짧게 다시 말하도록 안내하고 녹음을 자동 재시작한다.
- 생성 중에는 기리 토끼의 `다음 이야기를 만들고 있어!` 안내와 단순 반복 모션만 보여준다.
- 숫자 진행률은 사용하지 않으며, 본문과 배경 이미지가 모두 준비되기 전에는 다음 읽기 장면을 노출하지 않는다.

### 10.6 나의 성장

- 전체화면 정원 배경 위에 세 개의 화단을 배치한다.
- 화단은 흙, 새싹, 봉오리, 꽃, 만개의 5단계를 동일 캔버스 크기로 교체한다.
- 화단 단계는 성취율이 아니라 영역별 누적 학습 횟수로 성장하며 성취율 수치를 아동 화면에 표시하지 않는다.
- 파닉스, 읽기, 유창성 이름은 메인 지도와 같은 굵은 글자 체계를 사용한다.
- 이야기에서 해금한 친구만 정원에 놓을 수 있으며 미획득 캐릭터와 실루엣은 미리 표시하지 않는다.
- 정원에는 이야기 친구를 최대 4명까지 배치한다.
- 배치는 자유 좌표가 아니라 화면 비율이 달라져도 유지되는 네 개의 고정 슬롯을 사용한다.
- 배치 편집은 마우스·터치로 제공하고 시선 입력으로 캐릭터를 이동하지 않는다.
- 이야기 완료 후 `이야기 친구 보러 가기`를 선택하면 성장 정원 첫 빈 슬롯에 새 친구를 놓는다.
- 배치된 친구를 누르면 해당 이야기 제목을 포함한 짧은 감사 인사를 한다.

### 11.3 참고 순서

1. 새 화면과 가장 가까운 기존 Vue 화면을 확인한다.
2. `services/frontend-app/src/assets`에서 현재 실제 사용 중인 크기와 스타일을 확인한다.
3. `design-resources/public/assets`에서 같은 캐릭터나 오브젝트의 마스터를 찾는다.
4. 기존 마스터를 직접 덮어쓰지 않고 새 원본을 만든다.
5. 선택한 최종본만 앱 에셋 폴더에 복사한다.
6. Vue에서 import하고 `cover` 또는 `contain` 규칙을 명시한다.
7. `1280 × 720`과 `1920 × 1080`에서 잘림, 알파 테두리와 글자 대비를 확인한다.

### 11.4 파일명

신규 파일은 영문 소문자 케밥 표기를 권장한다.

```text
<domain>-<object>-<state>-<variant>.<ext>
```

예:

```text
island-main-base.png
island-main-hover-story.png
rabbit-reading-happy.png
training-platform-current.png
growth-field-phonics-stage-03.png
```

- 의미 없는 `최종`, `진짜최종`, `v6`를 파일명에 누적하지 않는다.
- 상태 교체 파일은 `base`, `hover`, `active`, `complete`, `locked`를 사용한다.
- 단계 이미지는 두 자리 숫자 `stage-01` 형식을 사용한다.

## 15. CSS 관리 구조

- Vue 파일에는 레이아웃과 동작만 두고, 스타일 본문은 `services/frontend-app/src/styles`에서 관리한다.
- Vue 파일의 `<style scoped src="...">` 연결은 유지해 기존 컴포넌트 스코프가 다른 화면에 새지 않게 한다.
- 전체 공통 글꼴, 글자 단계, 색상, 여백, 모서리, 그림자는 `styles/common/tokens.css`에서 관리한다.
- 폴더 역할은 `common`, `training`, `story`, `world`, `educator`로 구분한다.
- 실제 학습 종류별 CSS는 `styles/training/activities`에 둔다.
- 한 화면만 수정할 때는 해당 컴포넌트 CSS를, 여러 화면의 같은 역할을 수정할 때는 공통 토큰을 수정한다.
- 상세 파일 지도와 수정 순서는 `services/frontend-app/src/styles/README.md`를 기준으로 한다.

## 16. 화면 디자인 일관성 규칙

기능과 화면 흐름은 유지하되, 모든 화면은 아래의 동일한 화면 문법을 사용한다.

### 16.1 공통 헤더

- 왼쪽은 사용자 프로필, 중앙은 홈으로 이동하는 아이리드 로고, 오른쪽은 아이트래커·마이크·나가기 상태로 고정한다.
- 헤더 높이, 아이콘 크기, 좌우 여백은 모든 화면에서 공통 토큰을 사용한다.
- 화면 전환 중에도 헤더의 위치와 크기가 움직이지 않게 한다.
- 특정 공간 전용 기능을 헤더 안에 추가하지 않는다.
- `이야기 친구들`처럼 특정 공간에서만 쓰는 기능은 해당 콘텐츠 영역의 보조 버튼으로 배치한다.

### 16.2 뒤로가기와 모달 닫기

- 일반 하위 화면의 뒤로가기는 콘텐츠 영역 왼쪽 상단에 둔다.
- 공통 아이보리색 둥근 사각형과 진한 남색 화살표를 사용한다.
- 크기, 위치, 안전 여백은 `--learner-page-back-*` 토큰을 사용한다.
- 페이지 이동과 모달 닫기는 혼용하지 않는다.
- 페이지 이동은 왼쪽 상단 뒤로가기, 모달 닫기는 모달 오른쪽 상단 닫기 버튼을 사용한다.

### 16.3 패널과 카드

패널은 다음 세 종류만 사용한다.

1. 대형 콘텐츠 패널
   - 연한 크림색 또는 아이보리 배경
   - 흰색 또는 연한 베이지 테두리
   - 가장 큰 공통 모서리와 약한 하단 그림자
2. 선택 카드
   - 흰색 또는 아이보리 배경
   - 공통 카드 모서리와 그림자
   - 영역 포인트 색상은 아이콘, 테두리, 배지에만 사용
   - 카드 전체를 클릭 영역으로 사용
   - 글자 카드는 `1:1`, 낱말 카드는 약 `3:2`, 문장 카드는 약 `2:1` 비율을 사용
   - 3지선다는 노랑·민트·보라 실제 리소스를 같은 순서로 사용
3. 모달
   - 크림색 배경과 연한 테두리
   - 공통 모달 모서리와 그림자
   - 공통 딤 및 블러
   - 불필요한 이중·삼중 프레임 금지

### 16.4 모서리와 그림자

- 대형 패널은 `--learner-radius-panel`, 일반 카드는 `--learner-radius-card`, 버튼은 `--learner-radius-control`을 사용한다.
- 아이콘 버튼은 원형 또는 공통 둥근 사각형 중 지정된 한 형태를 사용한다.
- 그림자는 아래 방향의 부드러운 공통 그림자만 사용한다.
- 파란색, 회색, 진한 입체 그림자를 화면별로 혼용하지 않는다.
- 카드와 버튼 아래에 두꺼운 가짜 3D 바닥면을 만들지 않는다.

### 16.5 타이포그래피 계층

- 장식형 제목은 `이야기 나라`, `나의 성장`, `글자 연습`, `실력 도전`의 공간 대표 제목에만 허용한다.
- 공간 대표 제목의 흰 외곽선과 그림자 두께는 공통 토큰으로 관리한다.
- 내부 페이지 제목은 진한 남색, 굵은 단일 폰트, 공통 크기와 줄높이를 사용하며 외곽선과 입체 그림자를 사용하지 않는다.
- 학습 지시문은 내부 제목보다 한 단계 작고 행동 중심의 한 문장으로 작성한다.
- 설명과 보조 문구는 회청색으로 1~2줄만 사용하고 최소 글자 크기 이하로 줄이지 않는다.
- 읽기 본문은 진한 남색, 넓은 줄간격과 일정한 문단 간격을 사용한다.
- 기본 폰트는 화면 UI용과 읽기 본문용, 최대 두 종류만 사용한다.

### 16.6 영역 및 상태 색상

- 이야기 나라: 보라색
- 나의 성장: 초록색
- 글자 연습과 음운 훈련: 주황색
- 실력 도전: 파란색
- 음성 입력: 코랄색
- 완료: 초록색
- 오류: 코랄색 또는 붉은색
- 비활성 및 잠금: 회색
- 같은 학습 흐름의 시작 버튼, 진행 표시, 선택 상태는 같은 영역 색상을 유지한다.
- 정답·오답·잠금 같은 시스템 상태 색상은 영역 색상보다 우선한다.

### 16.7 버튼

- 화면의 가장 중요한 행동 하나만 채워진 포인트 색상의 주요 버튼으로 표시한다.
- 주요 버튼은 흰색 굵은 글씨, 공통 높이·패딩·모서리·그림자를 사용한다.
- 보조 버튼은 흰색 또는 아이보리 배경, 연한 테두리, 진한 남색 글씨를 사용한다.
- 비활성 버튼은 회색 배경과 낮은 글자 대비를 사용하고 그림자·호버 효과를 제거한다.
- 아이콘 버튼은 공통 최소 클릭 영역과 동일한 아이콘 크기·선 두께를 사용한다.

### 16.8 일러스트 범위

- 앱 UI의 헤더, 버튼, 카드, 학습 아이콘, 지도, 단계 발판, 배경 장식, 상태 안내는 밝은 2D 아동용 플랫 벡터로 통일한다.
- 수채화 스타일은 이야기 본문 삽화 프레임 내부에서만 허용한다.
- 같은 이야기의 썸네일, 본문, 질문 화면은 동일한 캐릭터 디자인과 화풍을 사용한다.
- 시각적 오브젝트와 의미 아이콘은 3.3의 리소스 우선 원칙에 따라 제작하며 CSS 도형, pseudo-element 그림, 텍스트 기호와 이모지로 대체하지 않는다.
- 새로운 이미지가 필요한 경우 `리소스 추가 필요` 상태를 사용하고 정식 리소스 제작 전까지 임시 그래픽을 최종 UI로 승인하지 않는다.
- 기존 앱 에셋과 디자인 리소스 폴더를 먼저 확인한다.

## 17. 진행도와 상태 표현

### 17.1 진행도

- 전체 학습 진행은 의미 문구, 진행 바, `3 / 10` 숫자를 함께 표시한다.
- 개별 문제 진행은 상세 화면 상단 중앙에 `1 / 5`를 표시하고 점은 보조로만 사용한다.
- 이야기 진행은 원형 진행률 또는 현재 페이지 중 하나만 사용한다.
- 단계 진행은 번호 배지, 완료 체크, 현재 포인트 색상, 잠금 회색과 잠금 아이콘을 사용한다.
- 오늘 학습량, 문제 개수, 전체 커리큘럼 진행도를 같은 의미처럼 혼용하지 않는다.

### 17.2 공통 상태

- 기본: 아이보리 또는 흰색 배경, 기본 테두리, 약한 그림자
- 호버: 약간 위로 이동하고 그림자만 소폭 강화하며 과도하게 확대하지 않음
- 키보드·시선 포커스: 두꺼운 포인트 색상 링과 충분한 대비
- 시선 선택 중: 원형 또는 테두리형 dwell 진행을 표시하고 설정 시간이 끝난 뒤 선택
- 선택: 포인트 색상 테두리와 옅은 배경
- 정답: 초록색 테두리 또는 배경, 체크, 짧은 긍정 피드백
- 오답: 코랄색 테두리, 약한 흔들림, 즉시 정답 노출 없이 재시도
- 완료: 초록색과 체크, 필요한 경우에만 별 또는 꽃 보상
- 잠금·비활성: 카드, 글자, 아이콘, 배지 전체를 회색 처리하고 잠금 아이콘 표시
- 로딩·분석: 공통 로딩 애니메이션과 현재 상태 문구 표시

## 18. 모든 훈련 상세 화면 공통 구조

첫소리 고르기, 같은 소리 찾기, 음절 합치기, 글자와 소리 연결, 단어 읽기, 문장 읽기, 유창성 읽기를 포함한 모든 상세 훈련은 아래 순서를 유지한다.

1. 공통 헤더
2. 왼쪽 상단 뒤로가기
3. 중앙 문제 진행도
4. 한 줄 학습 지시문
5. 문제 제시 영역
6. 사용자 응답 영역
7. 피드백 및 다음 행동 영역

- 지시문은 `첫소리를 골라!`, `같은 소리를 찾아!`, `문장을 읽어봐!`처럼 행동 중심의 친근한 반말로 작성한다.
- 문제 제시 영역에는 음성, 글자, 음절, 단어, 문장, 그림, 짧은 글, 읽기 위치 등 필요한 핵심 자극만 표시한다.
- 문제 제시 영역이 장식보다 먼저 보이고 화면에서 가장 큰 비중을 차지해야 한다.
- 응답은 선택 카드, 그림 카드, 글자 카드, 드래그 앤 드롭, 순서 배열, 음성 녹음, 읽기, 글자 입력, 연결하기 공통 모듈을 재사용한다.

### 18.1 글자 따라보기

- 읽기 영역은 장식 없는 흰색 블록을 사용하고 글자 획은 파란색 외곽선으로 표시한다.
- 움직이는 시선 점과 완료 후 회전하는 점선 원은 표시하지 않는다.
- 각 획의 시작점에는 `1`, `2`, `3`, `4`처럼 고정된 순서 번호만 표시한다.
- 마지막 지점을 읽으면 글자 안쪽을 하늘색으로 채우고 글자 중심에서 원형 파동을 한 번 퍼뜨려 완료를 알린다.
- 완료 파동 뒤에는 오른쪽 말하기 패널의 테두리를 코랄색으로 밝혀 다음 행동이 음성 입력임을 연결한다.
- 진행 표시 아래에는 `글자를 따라 읽어요!`처럼 행동을 설명하는 짧은 안내를 둔다.
- 오른쪽 위에는 공통 듣기 버튼만 배치하고 현재 글자를 중복해서 작게 표시하지 않는다.
- 획을 모두 따라가면 자모 이름 또는 음절 소리를 들려준 뒤 아동의 발음을 받는다.
- 오른쪽 아래 말하기 패널은 마이크 상태, 파형과 짧은 상태 문구로 녹음 중임을 표시한다.

### 18.2 음성 듣기

- 모든 훈련에서 동일한 스피커 아이콘, 위치와 크기를 사용한다.
- 화면에 보이는 버튼 문구 없이 기본·다시 듣기·재생 중의 서로 다른 정식 아이콘 리소스를 사용한다.
- 접근성 이름은 `소리 듣기`, 재생 후 `다시 듣기`, 재생 중 `재생 중`을 사용한다.
- 재생 중에는 전용 아이콘과 짧은 파동 움직임만 표시한다.
- 재생 상태에 `듣고 있어요`를 사용하지 않는다. 이 문구는 음성 녹음 상태에만 사용한다.

### 18.3 학습 진행 버튼

- 모든 학습 문제의 나가기와 다음 이동은 학습 창 왼쪽 위와 오른쪽 위에 고정된 같은 크기의 파란색 공통 화살표 리소스를 사용한다.
- 나가기는 굽은 왼쪽 화살표, 다음 이동은 오른쪽 화살표로 구분한다.
- 문제를 완료하기 전의 다음 이동은 연한 파란색 비활성 리소스로 표시하며 누를 수 없게 한다.
- 문제를 완료하면 같은 위치에서 선명한 파란색 활성 리소스로 바뀌고, 짧은 확대·축소와 푸른 빛 효과로 이동 가능 상태를 알린다.
- 버튼 안에는 아동이 읽어야 하는 문구를 넣지 않고 오른쪽 화살표만 표시한다.
- 액티비티 내부에는 별도의 `다음`, `다음 문제` 텍스트 버튼을 노출하지 않는다.

### 18.3 선택형 문제

- 선택지는 기본 2~4개를 사용한다.
- 카드 크기와 간격을 통일하고 카드 전체를 클릭할 수 있게 한다.
- 글자, 그림, 단어가 달라도 동일한 선택 카드 구조와 공통 상태 규칙을 사용한다.

### 18.4 드래그 앤 드롭

- 드래그 대상과 도착 영역을 명확히 구분한다.
- 잘못 놓은 항목은 원래 자리로 부드럽게 복귀한다.
- 시선 입력 환경에는 `대상 선택 → 위치 선택` 대체 방식을 제공한다.

### 18.5 순서 배열

- 카드와 슬롯 크기를 통일한다.
- 현재 선택 카드를 명확하게 표시한다.
- 배열 완료 전에는 다음 버튼을 비활성화한다.
- 전체 초기화 또는 한 단계 되돌리기를 제공한다.

### 18.6 음성 녹음

- 코랄색 마이크 버튼을 공통으로 사용한다.
- 녹음 전 `말해보세요`, 녹음 중 `듣고 있어요`, 분석 중 `읽은 내용을 확인하고 있어요`를 사용한다.
- 녹음 중에는 파형 또는 시간을 표시한다.
- 실패 시 다시 말하기 버튼을 제공한다.
- 재생과 녹음 상태는 문구와 색상 모두로 구분한다.

### 18.7 읽기

- 읽을 글은 화면 중심에 크게 배치한다.
- 글자 크기, 줄간격, 문장 간격은 공통 읽기 토큰을 사용한다.
- 긴 문장은 의미 단위로 줄바꿈한다.
- 현재 단어나 어절은 낮은 채도의 하이라이트를 사용한다.
- 배경 장식은 읽기 영역과 겹치지 않는다.

### 18.8 연결하기

- 시작 항목과 도착 항목을 두 영역으로 구분한다.
- 선택한 항목과 연결 가능한 대상만 강조한다.
- 연결선은 굵고 단순하게 표시하고 글자나 그림을 가리지 않는다.
- 잘못 연결한 경우 쉽게 취소할 수 있어야 한다.

## 19. 훈련 피드백과 내비게이션

### 19.1 정답과 오답

- 정답은 즉시 정답 카드 강조, 짧은 칭찬 음성과 1초 내외의 작은 별 반응으로 표시한다.
- 정답 후 자동 이동하거나 명확한 다음 버튼을 제공한다.
- 오답은 비난 표현을 사용하지 않고 `괜찮아!`, `한 번 더 해봐!`처럼 재시도 중심으로 표시한다.
- 힌트는 `문제 자극 재제시 → 핵심 소리·글자 강조 → 선택지 축소·약화 → 마지막 정답 안내` 순서로 제공한다.
- 첫 오답에는 문제 소리를 다시 들을 기회를 주고, 같은 문제에서 두 번 틀리면 오답 선택지를 약하게 낮추고 핵심 소리·글자를 힌트로 준다.

### 19.2 완료

- 모든 문제를 마친 뒤에만 완료 화면 또는 모달을 사용한다.
- 문제마다 모달을 띄우지 않는다.
- 완료한 문제 수와 다음 행동만 간단히 표시한다.
- 계속 학습, 다음 단계, 학습 종료 중 필요한 행동만 제공한다.
- 문제 풀이 중 2연속·3연속 같은 중간 연속 정답 축하는 제공하지 않는다.
- 정확히 5문제인 훈련을 오답 없이 완료하면 별 리소스와 특별 칭찬을 사용하는 `올정답 완료` variant를 표시한다.
- 한 번이라도 오답을 낸 경우에는 끝까지 해낸 노력을 칭찬하는 일반 완료 variant를 표시한다.

### 19.3 배치와 이동

- 콘텐츠는 중앙의 공통 대형 패널 안에 배치한다.
- 좌우 여백과 상하 간격은 모든 훈련에서 같은 토큰을 사용한다.
- 장식은 문제 영역 바깥에만 배치하고 빈 공간을 무조건 채우지 않는다.
- 한 화면에서는 한 문제와 한 핵심 행동에만 집중한다.
- 문제 풀이 중에는 이유 없이 다음 문제로 건너뛰는 버튼을 제공하지 않는다.
- 정답 또는 필수 응답 완료 뒤에만 다음으로 이동한다.
- 뒤로가기와 학습 종료는 구분하며, 종료 시 확인 모달에서 저장 여부와 이동 위치를 안내한다.

## 20. 화면별 추가 규칙

### 20.1 나의 성장

- `파닉스`, `읽기`, `유창성` 표지판의 크기, 글씨, 위치를 통일하고 확대한다.
- 표지판은 흙 위에 겹치지 않게 화단 앞쪽에 둔다.
- `이야기 친구들`은 헤더가 아닌 콘텐츠 영역의 보조 버튼으로 둔다.

### 20.2 이야기 나라 선택

- 하단 버튼은 `읽던 책 고르기`, `새 이야기 시작하기`로 표시한다.
- 두 버튼에는 위 행동 이름만 크게 표시하며 그 아래 작은 세부 설명은 넣지 않는다.
- 두 버튼의 카드 규격을 통일하고 주요·보조 행동의 색상 차이를 둔다.
- 썸네일과 본문 삽화의 캐릭터 및 화풍을 통일한다.

### 20.3 이야기 읽기와 음성 답변

- 본문 최대 너비와 줄 길이, 줄간격과 문장 간격을 제한한다.
- 페이지 또는 읽기 진행 표시 중 하나를 사용한다.
- 페이지 이동 버튼의 위치와 형태를 통일한다.
- 중앙 음성 답변 카드의 중첩 프레임을 줄인다.
- 녹음 상태에는 파형 또는 움직임을 표시한다.
- 음성 재생과 녹음 상태를 문구와 색상으로 구분한다.
- 마이크 버튼의 색상과 크기는 다른 음성 훈련과 동일하게 한다.

### 20.4 실력 도전 선택

- 일반 웹 대시보드 같은 3열 카드 대신 귀, 문장 카드, 책 등 구체적인 아동용 플랫 벡터 삽화를 사용한다.
- 설명은 줄이고 제목과 핵심 문구를 확대한다.
- 카드 전체를 클릭할 수 있게 하고 파란색 포인트를 강화한다.
- 공통 크림색 패널, 모서리, 그림자 규칙을 사용한다.

### 20.5 글자 연습 지도

- 상단 진행도가 오늘 진행인지 전체 진행인지 명확히 표시한다.
- 단계 번호 배지와 라벨 버튼의 크기·위치를 통일한다.
- 잠금 단계는 섬, 글자, 라벨, 경로 전체를 비활성화한다.

### 20.6 훈련 시작과 종료

- 시작 화면의 중앙 카드를 확대하고 공통 대형 패널을 사용한다.
- 예상 시간과 문제 수는 공통 정보 배지로 표시한다.
- 시작 버튼은 학습 영역 포인트 색상을 사용한다.
- 이미지가 없으면 임의 생성하지 않고 `리소스 추가 필요`로 표시한다.
- 종료 모달은 공통 모달과 버튼 규칙을 사용한다.
- 실제 진행 상태와 무관한 독려 문구를 반복하지 않는다.
- 현재 진행 저장 여부와 종료 후 이동 위치를 명확하게 안내한다.
