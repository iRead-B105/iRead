# ADR-0012: 위험 기반 경량 하네스 정책

- 상태: accepted
- 결정일: 2026-07-27
- 결정자: 사용자
- 부분 대체: [ADR-0007](ADR-0007-okf-and-specification-sources.md)의 저장소 전체 OKF 적용 범위

## 배경

같은 작업 절차와 완료 조건이 `AGENTS.md`, AI 워크플로, DoR·DoD와 실행 계획 규칙에 반복되어 변경 때 여러 문서를 동기화해야 했다. 모든 개념 문서에 수동 메타데이터와 로그·인덱스 갱신을 요구했지만, 활성 계획 상태와 현재 단계 같은 의미 불일치는 검증하지 못했다.

하네스 검증기는 저장소 전체를 재귀 탐색하여 Git에서 무시한 캐시와 submodule 문서까지 읽었다. 필수 파일은 특정 문서명을 수동 열거해 새 ADR과 계약이 추가될 때마다 검증기 수정이 필요했다.

## 결정

- `AGENTS.md`는 모든 프로젝트 사실을 복제하지 않고 작업 경계와 기준 문서 탐색 방법만 제공한다.
- 확인, 계획과 검증 강도는 변경 위험에 비례한다.
- 실행 계획은 여러 세션, 여러 서비스 계약, 마이그레이션, 보안·배포 또는 장기 차단을 추적할 때만 작성한다.
- 동작 변경이나 검증 공백이 있을 때 테스트를 추가·수정한다. 기존 테스트가 충분하면 관련 테스트 실행만으로 완료할 수 있다.
- 메타데이터 강제 범위는 ADR, 실행 계획과 승인 기능 명세로 제한하고 `type`만 필수로 둔다. 제목은 H1, 변경 시각은 Git 이력을 기준으로 한다.
- 기존 일반 문서의 frontmatter는 즉시 제거하지 않아도 되지만 새로 강제하거나 수정 시각을 일괄 갱신하지 않는다.
- 인덱스는 문서 추가·삭제·이름 변경 때 갱신하고, `docs/log.md`는 주요 기준선과 정책 변경만 기록한다.
- 하네스 검증은 Git이 추적하거나 새로 추가한 오케스트레이션 파일만 검사한다.
- 필수 파일은 탐색 진입점과 핵심 기준 문서로 제한하고, ADR 등록처럼 동적으로 확인할 수 있는 관계는 파일명 목록 대신 규칙으로 검증한다.

## 영향

### 긍정적 영향

- 작은 변경에서 작성·검토해야 하는 정책 문서와 체크리스트가 줄어든다.
- 검증이 로컬 캐시와 submodule 내부 상태에 영향을 받지 않는다.
- 테스트와 계획 의무가 변경 위험에 맞춰진다.
- 중요한 기록 문서의 추적성과 계약 기준 원본은 유지된다.

### 부정적 영향과 대응

- 일반 문서 메타데이터의 형식 통일성은 낮아질 수 있다. 탐색은 디렉터리와 인덱스 링크를 기준으로 한다.
- 위험 판단에 재량이 생긴다. API, 데이터, 보안, 외부 시스템과 파괴적 작업은 계속 사용자 확인 대상으로 유지한다.
- 기존 문서에는 이전 OKF frontmatter가 남는다. 별도 일괄 정리 작업 없이 문서 목적에 필요할 때만 제거한다.

## 검증 및 재검토 조건

- 하네스 검증기 단위 테스트에서 무시 파일 제외, 기록 문서 메타데이터와 ADR 인덱스 등록을 확인한다.
- 규칙 완화로 반복적인 누락이 발생하면 해당 위험에 한정된 자동 검증을 추가한다.
- 일반 문서 검색성이 실제로 저하되면 메타데이터 강제 대신 검색 인덱스 자동 생성을 우선 검토한다.
