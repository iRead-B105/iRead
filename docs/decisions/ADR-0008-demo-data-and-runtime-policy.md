# ADR-0008: 데모 데이터 보관과 실행 환경 정책

- 상태: accepted
- 결정일: 2026-07-24
- 결정자: 사용자
- 대체 대상: 없음

## 배경

iRead는 실제 운영까지 진행하지 않는 데모 버전이다. 운영 서비스 수준의 고가용성, 재해 복구와 감사 인프라는 현재 범위에 맞지 않지만, 연구·분석 목적으로 음성 원본과 보고서를 장기간 보관할 가능성과 데모 API의 기본 보호 기준은 명확히 해야 한다.

## 결정 기준

- 데모를 재현할 수 있어야 한다.
- 운영 인프라 비용과 관리 범위를 만들지 않아야 한다.
- 연구·분석 데이터의 장기 보관은 정보 주체가 동의한 범위를 넘지 않아야 한다.
- 데모에서도 인증 정보와 개인정보가 불필요하게 노출되지 않아야 한다.

## 검토한 대안

1. 운영 서비스와 동일하게 관리형 MySQL, 백업·복구와 감사 인프라를 구성한다.
2. 모든 데이터에 짧은 고정 보관 기간을 적용한다.
3. 데모 환경은 폐기 가능하게 유지하고, 별도 동의를 받은 연구·분석 데이터에만 동의서에 명시한 기간의 장기 보관을 허용한다.

## 결정

### 데이터 보관

- 음성 원본과 보고서를 연구·분석 목적으로 장기간 보관할 수 있다.
- 장기 보관은 수집 항목, 목적, 보관 기간, 접근 주체, 철회와 삭제 방법을 명시한 별도 동의를 받은 데이터에만 적용한다.
- 동의서에 보관 기간이 없거나 동의를 확인할 수 없는 데이터는 장기 보관하지 않는다.
- 동의 철회 또는 명시한 보관 기간 종료 시 해당 원본과 연결 가능한 파생 데이터를 삭제한다.
- 음성 파일 경로는 외부에 직접 공개하지 않고 인증된 Backend를 통해서만 접근한다.

### MySQL 실행 환경

- 데모는 로컬 또는 Docker MySQL을 사용한다.
- 스키마와 데모 데이터는 Backend Flyway migration과 비식별 seed 데이터로 재현한다.
- RDS, Multi-AZ, 운영 백업·복구와 재해 복구 구성은 현재 범위에서 제외한다.
- 데모 데이터베이스는 폐기 가능한 환경으로 취급하며 실제 사용자 데이터의 영구 저장소로 사용하지 않는다.

### API 권한과 로그

- 데모에서도 인증 여부, 사용자 역할과 리소스 소유권을 검사한다.
- 토큰, 비밀번호, 이름, 연락처, 음성 파일 경로·접근 URL과 요청 본문은 로그에 기록하지 않는다.
- 별도의 운영용 감사 로그, 보안 관제와 장기 로그 보관 인프라는 구성하지 않는다.

## 영향

### 긍정적 영향

- 운영 인프라 없이 동일한 데모 환경을 반복해서 만들 수 있다.
- 연구·분석 목적의 장기 데이터가 별도 동의 범위로 제한된다.
- 데모 공개나 시연 과정의 기본적인 권한 우회와 로그 노출 위험을 줄인다.

### 부정적 영향과 트레이드오프

- 데모 데이터베이스 장애 시 자동 복구와 가용성을 보장하지 않는다.
- 별도 동의 데이터의 보관 기간과 삭제 일정을 데이터셋별로 관리해야 한다.
- 운영 환경으로 전환할 때 데이터 이전, 백업·복구, 접근 통제와 감사 정책을 새로 설계해야 한다.

## 검증 및 재검토 조건

- 데모 환경은 빈 MySQL에서 Flyway와 seed 데이터로 재현할 수 있어야 한다.
- 실제 사용자에게 공개하거나 실제 개인정보를 서비스 운영 목적으로 수집하기 전에 이 결정을 재검토한다.
- 운영 전환 시 관리형 MySQL 토폴로지, 백업·복구 목표, 수치화한 보관 기간, 접근 통제, 감사 로그와 사고 대응 정책을 새 ADR로 결정한다.
