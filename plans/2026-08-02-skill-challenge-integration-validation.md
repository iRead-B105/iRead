# 실력 도전 기준 데이터 정합화와 통합 검증

- 상태: active
- 작성일: 2026-08-02
- 수정일: 2026-08-02

## 목표

훈련 이력이 없는 학습자가 실력 도전 9문제를 완료하고, 교수자가 저장된 검사 결과와 추천 훈련을 검수한 뒤, 최종 검수된 훈련을 아동 App에서 시작하는 흐름을 같은 ID와 상태로 재현한다.

작업은 다음 순서를 고정한다.

1. 기준 데이터 일치
2. DB 관계 정합성 검사
3. Backend 실제 동작 검사
4. App·Web API 연동 검사
5. 발견된 코드·API 문제 수정
6. 빈 DB·기존 DB 회귀검사

앞 단계가 실패하면 뒤 단계 결과를 정상으로 판정하지 않는다. 3·4단계에서는 현재 동작을 먼저 재현하고 증빙하며, 기준 데이터 보정을 제외한 기능 오류는 5단계에서 수정한다.

## 범위

### 포함

- Backend 기준 데이터와 Flyway migration
- 단원·템플릿·검사·제출·추천·훈련 데이터 관계
- 최초 학습자의 실력 도전 9문제 생성·저장·완료
- 검사 결과 기반 약점 계산과 추천 커리큘럼 5개 생성
- AI 서버 최소 HTTP 연결과 생성 상태 DB 저장
- 교수자 Web의 검사 이력, 실제 제출 결과와 생성·검수 상태
- 아동 App의 필수 진입, 9문제 수행과 검수 완료 훈련 노출
- 빈 운영형 DB와 기존 데이터 DB 복제본 회귀검증
- 기존 홈, 이야기 나라와 일반 훈련 회귀검증
- 서비스 병합 후 orchestration submodule 갱신과 GitLab 투영 검증

### 제외 또는 보류

- 공용·운영 DB 직접 변경
- 완료 검사·훈련 이력의 소급 재작성
- 모든 AI 콘텐츠의 품질 평가
- Azure Speech 전체 실서비스 검증
- GitLab `main` 직접 수정
- OpenAPI 전체 갱신과 계약 원본 동기화

OpenAPI 갱신은 사용자 결정으로 보류한다. 실행 중 API 표현을 바꾸면 영향과 전환 내용을 문제 기록과 테스트에 남기지만, 계약 동기화 전에는 계약 작업까지 완료됐다고 판정하지 않는다.

## 공통 작업과 승인 경계

각 단계는 다음 순서로 진행한다.

1. 해당 저장소의 깨끗한 `develop`을 원격 최신 상태로 맞춘다.
2. `feature/<short-description>` 브랜치를 만든다.
3. 단계 범위의 구현 또는 진단을 수행한다.
4. 관련 테스트와 영향 검증을 수행한다.
5. 변경·검증·남은 위험을 사용자에게 보고한다.
6. 커밋 승인을 받는다.
7. 한국어 Conventional Commit을 만들고 표시 상태를 확인한다.
8. push 승인을 받는다.
9. 한국어 제목·본문의 PR 생성 승인을 받는다.
10. PR 검토 결과를 보고하고 merge 승인을 받는다.
11. squash merge와 브랜치 삭제를 확인한다.
12. orchestration submodule 참조를 별도 PR로 갱신한다.
13. Harness Validation과 GitLab Monorepo Sync 성공을 확인한다.

계획 승인에는 커밋, push, PR 생성과 merge 승인이 포함되지 않는다.

## 서비스 병합 후 GitLab 동기화

서비스 단계가 병합될 때마다 다음 절차를 수행한다.

1. 서비스 `develop`의 병합 커밋과 원격 push를 확인한다.
2. orchestration `develop`을 최신화한다.
3. `chore/update-<service>-pointer` 브랜치를 만든다.
4. 해당 `services/*` gitlink를 원격 서비스 `develop`로 이동한다.
5. staged submodule diff와 원격 커밋 존재 여부를 확인한다.
6. `chore(submodule): <서비스> develop 참조 갱신` 형식의 한국어 커밋을 승인받아 만든다.
7. 한국어 제목·본문 PR을 승인받아 생성하고 검토 후 병합한다.
8. Harness Validation과 GitLab Monorepo Sync를 확인한다.
9. GitLab `main`의 `.gitlab-source-revisions.json`과 `services/*` 파일을 원본 SHA와 비교한다.
10. 투영 commit의 한국어 메시지, 작성자 이름과 작성 시각 보존을 확인한다.

GitLab `main`과 `services/*`에는 직접 커밋하지 않는다. 자동 동기화 실패 시 먼저 원인을 보고하고, 일반 수동 재실행으로 해결 가능한 경우에도 승인을 받은 뒤 실행한다. 이력 재구성이나 upstream ref 정합화는 별도 장애 검토와 승인이 필요하다.

- 기존 ID를 재발급하면 과거 결과 연결이 끊기므로 알려진 기준 필드만 보정한다.

- orchestration 포인터는 검증된 이전 서비스 commit으로 되돌리는 PR을 사용한다.
- GitLab 투영은 원본 GitHub와 orchestration을 기준으로 복구하며 GitLab에서 직접 수정하지 않는다.
